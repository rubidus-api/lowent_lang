# `lowdiff` 매뉴얼

## 부르는 법

```
lowdiff <폴더A> <폴더B>
```

## 짓는 법

```sh
impl/build/lowentc --emit-c apps/lowdiff/src/lowdiff.low > /tmp/lowdiff.c
cc -O2 -o /tmp/lowdiff /tmp/lowdiff.c -lm
/tmp/lowdiff before/ after/
```

VM 으로도 같은 답을 낸다(대조용):

```sh
impl/build/lowentc --run main apps/lowdiff/src/lowdiff.low before/ after/
```

## 무엇을 내나

한 줄이 **하나의 발견**이다. 순서는 결정적이다 — 디렉터리마다 이름 오름차순, 공통 하위
디렉터리는 그 뒤에 이어 걷는다.

| 줄 | 뜻 |
|---|---|
| `added <길>` | B 에만 있다 |
| `deleted <길>` | A 에만 있다 |
| `changed <길>` | 양쪽에 있는데 **내용이 다르다** |
| `unreadable <길>` | 열지 못했다 — 「같다」도 「없다」도 **아니다** |
| `skipped <길>` | 한도에 걸려 보지 못했다 |

☞ `unreadable` 과 `skipped` 이 따로 있는 까닭: 못 본 것을 「같다」쪽에 넣으면 도구가
**조용히 거짓말을** 한다. 그래서 따로 말하고, 그 자리에서 멈추지도 않는다.

## 종료 코드

| 코드 | 뜻 |
|---|---|
| 0 | 같다 |
| 1 | 차이가 있다 |
| 2 | 사용법 |
| 3 | 내부 한도를 넘었다 — **조용히 자르지 않는다** |

## 어떻게 재나 (메모리가 파일 수와 무관한 까닭)

경로를 다 모으지 않는다. **디렉터리 쌍 단위로 나란히 걷는다** — 한 디렉터리의 엔트리만
양쪽에서 읽어 정렬·합치고, 공통 하위 디렉터리는 대기 목록에 넣는다. 파일 내용도 청크로
읽는다. 그래서 50 MB 짜리 파일이 있어도 버퍼는 그대로다.

한도(여기까지는 본다): 한 디렉터리 엔트리 4096 · 이름 바이트 262144 · 대기 4096.
넘치면 `skipped` 으로 **말하고**, 3 으로 끝난다.

## 오늘의 한계 (정직하게)

- 심링크를 **구분하지 못한다** — `file_type` 이 `stat` 이라 심링크는 그것이 가리키는
  것으로 보인다. 「따라가지 않고 제외 보고」하려면 `lstat` 자리가 필요하다.
- 권한·소유자·시각은 보지 않는다. 이 도구가 답하는 물음은 **「내용이 같은가」** 하나다.

## 바깥 오라클

`diff -rq <A> <B>` — 같은 나무에 대해 같은 발견을 말해야 한다.
