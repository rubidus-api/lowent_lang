# aes — AES-128 블록 암호

소스: `lib/aes.low` · 모듈명 `aes` (FIPS 197 · RFC-0090 N7b③)

> ## ⚠ 무엇을 약속하고 무엇을 안 하나
>
> · **상수시간을 약속하지 않는다** · **감사받지 않았다** · **비트슬라이싱은 안 지었다**.
> · **AES-NI 를 안 쓴다** — 이것은 순수 Lowent 구현이다. 처리량이 필요하면
>   [gcm](gcm.md) 대신 [aead](aead.md)(ChaCha20-Poly1305)를 **먼저 고려하라**.
> · **혼자 쓰는 모듈이 아니다.** 블록 암호는 그 자체로 안전한 통신을 주지 않는다 —
>   운용 모드가 있어야 한다. 여기서는 [gcm](gcm.md) 이 그 자리다.
> · 키 길이는 **128 비트뿐**이다(192·256 은 없다).

## 처음 쓰는 사람에게

**무엇을 하는 모듈인가.** 16 바이트를 키로 뒤섞어 16 바이트를 낸다. 그게 전부다 —
길이가 안 변하고, 인증도 없고, 같은 입력은 언제나 같은 출력을 낸다.

**그래서 이걸 직접 쓰면 대개 틀린다.** 같은 평문 블록이 같은 암호문 블록이 되므로
패턴이 그대로 보이고, 상대가 암호문을 **고쳐도 알 수 없다**. 실제로 필요한 것은
[gcm](gcm.md) 의 `encrypt`/`decrypt` 이고, 이 모듈은 그 밑에 깔린 부품이다.

**왜 TLS 에 필요한가.** TLS 1.3 은 `TLS_AES_128_GCM_SHA256` 을 **MUST** 로 요구한다
(RFC 8446 §9.1). 즉 이 모듈이 없으면 규격을 만족하는 구현이 아니다.

## 표면

| op | 하는 일 | 요구 |
|---|---|---|
| `gmul` | GF(2^8) 곱 (기약다항식 `0x11b`) | — |
| `ginv` | GF(2^8) 역원 — `x^254` 로 낸다(페르마) | `0` 의 역원은 `0` |
| `sbox` | S-box **한 바이트** — 표가 아니라 **정의로 계산**한다 | — |
| `inv_sbox` | 역 S-box | — |
| `expand_key` | 16 바이트 키 → 라운드 키 176 바이트 | `rk ≥ 176` · `key ≥ 16` |
| `encrypt_block` | `st` 16 바이트를 **제자리에서** 암호화 | `rk ≥ 176` · `st ≥ 16` · `tmp ≥ 16` |

☞ **복호 블록은 없다.** GCM 은 카운터 모드라 **암호화만** 쓴다 — 복호도 암호화로 한다.
  `inv_sbox` 가 있는 것은 그것을 언젠가 지을 자리를 비워 둔 것이지 지었다는 뜻이 아니다.

## ★ S-box 를 표로 적지 않는다

256 개 상수를 손으로 옮겨 적는 대신 **정의를 그대로 쓴다**:

```
S(x) = 아핀변환( x^(-1) in GF(2^8) ),   x = 0 이면 역원 자리에 0
```

역원은 `x^254 = x^(2^8-2)` 로 낸다(페르마의 소정리).

☞ 이 저장소는 상수를 옮겨 적다 **두 번 데였다.** 옮겨 적을 표가 없으면 옮겨 적다 틀릴
  일도 없다. 게이트는 계산한 256 개를 정본 표와 대조한다 — *계산이 맞는지를* 잰다.

## ★ 성능 — 재 보니 이랬다 (2026-08-21)

| | |
|---|---:|
| `sbox` 한 번 (계산) | **180 ns** |
| `sbox` 한 번 (표를 읽는다면) | 7.5 ns |
| `encrypt_block` 한 블록 | **30,827 ns** — 그중 `sbox` 160 회가 **93 %** |
| AES-128-GCM 전체 | **0.46 MB/s** |
| 견줌: ChaCha20-Poly1305 | **41.8 MB/s** |

**그리고 그중 15 배는 이미 갚았다.** `ginv` 가 `x^254` 를 **254 번 곱하고** 있었다.
제곱-곱으로 바꾸니 곱셈이 254 → 15 이고 GCM 이 0.03 → 0.46 MB/s 가 됐다.
오라클 96 자리는 **한 자리도 안 움직였다** — 답이 아니라 **가는 길**만 바뀐 것이다.

☞ **표를 쓰면 얼마나 더 빨라지나 — 그리고 왜 안 쓰나.** 산수는 명확하다: `sbox` 가
블록의 93 % 이고 표가 ×24 이므로 블록이 ×9.6, GHASH(회당 3,169 ns)까지 합치면 GCM 은
약 **2.5 MB/s**. **그래도 ChaCha20 보다 17 배 느리다.** 그런데 표는 **비밀 색인 캐시
부채널**을 들여온다 — AES 의 고전적인 공격 자리다.
⇒ *17 배 느린 채로 남는 대비책*을 위해 부채널을 사지 않는다.

★ 그러므로 **스위트 선호는 ChaCha20-Poly1305 다**([gcm](gcm.md) 참조). AES-128-GCM 은
규격이 MUST 라 **정확하게** 있는 것이고, 빠르라고 있는 것이 아니다.
