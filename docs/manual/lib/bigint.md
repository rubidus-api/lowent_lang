# bigint — 큰수 모듈러 산술

소스: `lib/bigint.low` · 모듈명 `bigint` (RFC-0090 N7b⑤)

> ## ⚠ 무엇을 약속하고 무엇을 안 하나
>
> · **상수시간을 약속하지 않는다** · **감사받지 않았다**.
> · **필요한 만큼만 지었다** — RSA **검증**(`s^e mod n`)에 드는 것뿐이다.
> · **큰수 나눗셈이 없다**(몽고메리 곱이면 안 써도 된다) · **음수가 없다** · **GCD·역원이 없다**.
> · 지수 `e` 는 **u64 하나**다 — RSA 의 공개 지수(보통 65537)를 담으려고 그렇게 좁혔다.

## 처음 쓰는 사람에게

**무엇을 하는 모듈인가.** u64 하나에 안 들어가는 수를 **모듈러 곱하고 거듭제곱한다.**
RSA 의 2048 비트 수 같은 것이다.

**왜 이렇게 인색한가.** 이 저장소는 *"안 지은 것은 틀릴 수도 없다"* 를 규율로 적어 두었다.
RSA 검증에 필요한 것은 `s^e mod n` 하나이므로, 나눗셈도 역원도 **안 지었다**.

> ★ **2026-08-20 에 목표가 바뀌었다.** 서명 **생성**을 짓기로 했다(공개 웹 HTTPS 서버).
> 그러면 이 모듈에 없던 것(모듈러 역원 등)이 필요해질 수 있다. 다만 **필요해질 때 짓는다** —
> 원칙이 뒤집힌 게 아니라 **범위가 넓어질 뿐**이다.

## ★ 표현 — 조각 폭은 누산이 정한다

**16 비트 조각(limb)** 을 u64 에 담고 **리틀엔디언 순서**로 늘어놓는다.

왜 16 인가. 곱이 `16×16 = 32` 비트이고, 128 조각을 더해도 `2^39` 라 u64 안에서 안전하다.
**32 비트 조각을 쓰면** 곱이 `2^64` 에 닿아 **누산이 넘친다**.

☞ *"레지스터가 64 비트니 조각도 64 비트"* 가 자연스러워 보이지만 틀린다. **조각 폭을 정하는
  것은 곱이 아니라 누산이다.**

## 표면

| op | 하는 일 | 요구 |
|---|---|---|
| `zero` | `a` 의 앞 `k` 조각을 0 으로 | `a ≥ k` |
| `from_bytes` / `to_bytes` | **빅엔디언** 바이트 ↔ 조각 | RSA 의 인코딩이 빅엔디언이다 |
| `from_bytes_le` / `to_bytes_le` | **리틀엔디언** 바이트 ↔ 조각 | 곡선 쪽 관례 |
| `ge_mod` | `a ≥ n` 인가 (0/1) | `k` 조각 비교 |
| `dbl_mod` | `a ← 2a mod n` | `R^2` 를 만드는 데 쓴다 |
| `mont_mul` | `out ← a·b·R^-1 mod n` (CIOS) | 아래 참조 |
| `n0inv16` | `-n^-1 mod 2^16` — 몽고메리의 상수 | `n` 의 **맨 아래 조각**만 받는다 |
| `mod_exp` | `out ← bse^e mod n` | `e` 는 u64 |

## ★ 왜 몽고메리인가 — 나눗셈을 안 짓기 위해서다

보통의 모듈러 곱은 `a·b mod n` 이고 그 `mod` 가 **큰수 나눗셈**이다. 몽고메리 곱은 대신
`a·b·R^-1 mod n` 을 내는데, `R = 2^(16k)` 이라 나누기가 **시프트**가 된다.

그 대가로 값을 "몽고메리 영역" 으로 옮겼다 되돌려야 하고, `R^2 mod n` 이 필요하다.
그것도 나눗셈 없이 얻는다 — **1 을 `2·16k` 번 배로 늘리면서**(`dbl_mod`) 넘칠 때마다
`n` 을 뺀다. 뺄셈만 쓴다.

☞ 이것이 이 모듈의 설계 전체다: **나눗셈을 안 지으려고 곱을 바꿨다.**
