# hash — 해시 (해시맵 자리 · 손상 검출)

소스: `lib/hash.low` · 모듈명 `hash` (RFC-0090 N3)

## 처음 쓰는 사람에게

**무엇을 하는 모듈인가.** 바이트열에서 수를 낸다. 쓸모가 **둘**이고, 그 둘을 섞으면 안 된다.

**권한이 없다.** 순수 계산이라 세상에 안 닿는다 — `cap` 을 하나도 안 받는다.

> ## ⚠ **`of` 와 `crc` 는 암호용이 아니다** — `digest` 는 다르다
>
> 이 모듈에는 **성격이 다른 셋**이 있다. 섞으면 위험한 쪽으로 틀린다:
>
> · `of`(FNV-1a 64) — **해시맵 자리**. 빠르고 잘 흩어진다. 암호용이 **아니다**.
> · `crc`(반사 CRC-32) — **우연한 손상** 검출. **위조를 막지 못한다**(원하는 CRC 를 맞추는 것은 쉽다).
> · `digest`/`digest_ok`(**SHA-256**) — 암호 해시. 무결성 증명은 **이쪽**이다.
>
> ⇒ 비밀·서명·무결성에 `of` 나 `crc` 를 쓰지 마라. 키가 있는 인증은 `digest` 도 아니고
>   `hmac` 이다(해시 하나로는 *누가 보냈는가* 를 답할 수 없다).

**최소 예제.**

```lowent
use hash .

fn slot input key slice u8 . input nslots u64 . output u64 . do
  return hash.bucket_of key nslots .      rem 해시맵의 칸 고르기
end

fn intact input data slice u8 . input want u64 . output bool . do
  return hash.crc_ok data want .          rem 저장/전송 중 손상됐나
end
```

## 왜 알고리즘을 고정했나

해시는 *"그럴듯한 수"* 가 나오면 맞아 보인다. 고정하지 않으면 **검사할 것이 남지 않는다.**
고정했기에 표준이 정한 검사값이 오라클이 된다(CRC-32 의 `"123456789"` → `0xCBF43926`),
그리고 두 뒤끝(VM·네이티브)이 갈리면 **그 자리에서** 드러난다.

## 표면

| op | 모양 | 쓸모 |
|---|---|---|
| `of` | `(data slice u8) → u64` | FNV-1a 64 — **해시맵 자리** |
| `bucket_of` | `(data, nslots u64) → u64` | 칸 고르기(나머지 연산) |
| `bucket_mask` | `(data, mask u64) → u64` | 칸이 2의 거듭제곱일 때 |
| `crc` | `(data slice u8) → u64` | 반사 CRC-32 — **손상 검출** |
| `crc_ok` | `(data, want u64) → bool` | 검사값 대조 |
| `maybe_same` | `(a, b slice u8) → bool` | 해시가 같은가 — **같다는 증명이 아니다**(이름이 그렇게 말한다) |
| `digest` | `(data, out mut slice u8) → u64` | **SHA-256** — 쓴 바이트 수(32) |
| `digest_ok` | `(data, out mut slice u8, want slice u8) → bool` | 받은 다이제스트와 **대조** |

★★ `digest_ok` 가 있는 이유: 해시는 **왕복이 아니라 대조**가 오라클이다. 다시 계산해 **받은
것과 맞대는** 것이 유일하게 옳은 쓰임이고, 그래서 그 모양이 op 으로 있다(`want` 가 32 바이트가
아니면 그대로 false — 길이부터 계약이다).

★ `maybe_same` 의 이름에 `maybe` 가 있는 이유: 해시가 같아도 값이 같다는 뜻은 아니다.
**이름이 약속을 넘지 않게** 지은 것이고, `same` 이라 불렀으면 그 이름이 거짓말이 됐을 것이다.

## 안 지은 것 (정직히)

키드 해시(그 자리는 `hmac`) · 시드 가능한 해시(HashDoS 방어) · 스트리밍(조각으로 이어 먹이기) ·
SHA-256 **말고 다른** 암호 해시.

☞ 그리고 **`lib/hash.low` 의 머리 주석이 낡았다**: *"그 자리는 SHA-256 이고 아직 없다"* 고 적혀
  있는데 `digest` 가 바로 그것이다(RFC-0090 N3c 로 들어왔다). 이 매뉴얼을 쓰다 발견했고,
  범위 밖이라 티켓으로 넘겼다 — **문서가 코드보다 오래 산다는 것을 또 한 번 본다.**
