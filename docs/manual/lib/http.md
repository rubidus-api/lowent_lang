# http — HTTP/1.1 요청 파서

소스: `lib/http.low` · 모듈명 `http` (RFC 9112 · RFC-0090 §N6)

> ## ⚠ 무엇을 약속하고 무엇을 안 하나
>
> · **서버 쪽 요청 파싱만** 한다. 응답 파싱(클라이언트 쪽)은 없다.
> · **전송이 없다.** 소켓도 재조립도 없다 — 바이트열은 부르는 쪽이 모아 온다.
> · **청크 전송(`Transfer-Encoding: chunked`)을 안 짓는다.** 그 헤더를 찾아 주기만 하고,
>   **거절은 부르는 쪽의 정책**이다 — 다만 해체를 안 지었으므로 **거절해야 한다**.
> · 트레일러 · 여러 줄 헤더(obs-fold, 규격이 폐기했다) · URL 퍼센트 해체 · HTTP/2 없음.
> · **HTTP/1.0 을 안 받는다** — 지속 연결 규칙이 다르고 그것을 안 지었다.

## 처음 쓰는 사람에게

**무엇을 하는 모듈인가.** 요청 바이트열을 받아 **어디서 시작해 몇 바이트인지** 답한다.
자르지 않는다 — 자르는 것은 부르는 쪽이 `subslice` 로 한다([der](der.md) 과 같은 모양이다).

**모든 실패는 `0` 이다.** 예외가 아니라 값이다. `0` 은 정당한 자리가 될 수 없다 — 요청은
최소 `GET / HTTP/1.1␍␊␍␊` 라서 어떤 필드도 0 에서 시작하지 않는다.

```lowent
rem 자리를 받아 부르는 쪽이 자른다
let t u64 be http.target_off b .
let n u64 be http.target_len b .
guard gt n 0 . else return 0 .
let target slice u8 . be subslice b t (add t n) .
```

## 표면

| op | 하는 일 |
|---|---|
| `method_get`·`method_head`·`method_post`·`method_put`·`method_delete` | 메서드 코드(1~5) |
| `method_code` | 요청 줄의 메서드 → 코드. **0 = 모름** |
| `line_next` / `line_len` | 다음 줄의 자리 / 이 줄의 내용 길이(CRLF 제외) |
| `target_off` / `target_len` | 요청 대상의 자리 / 길이 |
| `version_ok` | `HTTP/1.1` 인가 |
| `headers_off` / `header_next` | 첫 헤더 / 다음 헤더 (**빈 줄이면 0**) |
| `name_len` / `value_off` / `value_len` | 헤더 이름 길이 / 값 자리 / 값 길이 |
| `name_eq` | 이 헤더의 이름이 그것인가 (**대소문자 안 가림**) |
| `header_find` / `header_find_len` | 그 이름의 값 자리 / 길이. **중복이면 0** |
| `content_length` | `option u64` — 없으면 **`some 0`**, 성하지 않으면 **`none`** |
| `body_off` | 몸통이 시작하는 자리 |

## ★★★ 이 모듈의 알맹이는 **거절**이다

파서는 받아들이는 것보다 **거절하는 것**으로 정의된다. 그리고 HTTP 에서 잘못 받아들이는
자리에는 이름이 있다: **요청 밀반입(request smuggling)**. 앞단(프록시)과 뒷단(서버)이 같은
바이트를 **다르게 읽으면**, 하나가 본 요청을 다른 하나는 못 본다.

골든이 아홉 가지를 본다:

| 거절하는 것 | 왜 |
|---|---|
| 맨 `LF` 를 줄 끝으로 | 앞단이 CRLF 만 인정하면 경계가 갈린다 |
| 이름과 콜론 사이 공백 (`Host : x`) | RFC 9112 §5.1 이 거절을 요구한다 |
| `Content-Length` 가 둘 | **값이 같아도** 거절한다 |
| `Content-Length: 5, 5` · `+5` · 빈 값 | 숫자만 받는다. **그 관용이 밀반입이다** |
| `HTTP/1.0` | 지속 연결 규칙이 다른데 안 지었다 |
| 같은 헤더가 둘 (`header_find`) | 합쳐도 되는지는 헤더마다 다르고 그 표를 안 지었다 — **모르면 거절** |
| 빈 대상 (`GET  HTTP/1.1`) | |
| 안 끝난 헤더 (빈 줄 없음) | |

## ★ `content_length` 가 `option` 인 이유

*"없다"* 와 *"틀렸다"* 는 **다른 답**이다:

- 없으면 **`some 0`** — 몸통이 없는 정상 요청이다.
- 성하지 않으면 **`none`** — **연결을 끊어야 할 일**이다.

한 값으로 두면 그 둘이 섞이고, 섞이는 자리가 곧 공격 자리다.
([files](files.md) 의 `read_dir` 이 *"못 읽었다"* 와 *"더 없다"* 를 가르는 것과 같은 이유다.)

## ★★★★ 이 모듈이 컴파일러 결함을 하나 잡았다

처음에 `input b str .` 로 썼다. `--check` 는 **초록**이었는데 21 op 중 **16 이 해석기로
떨어졌다**(~80배). `str` 은 빌트인이 아니라 [strings](strings.md) 의 **지역 별칭**이고,
검사기는 그 이름을 *"이름만 받는 목록"* 으로 통과시키는데 **하강은 뜻을 모른다.**

**답은 맞으므로 오라클이 영원히 못 본다.** 조용한 80 배다.

⇒ 이제 그런 이름을 시그니처에 쓰면 **`W-NOT-YET` 경고가 나온다**(직접 선언한 곳은 조용하다).
  ☞ 교훈: *검사가 초록인 것과 빠른 것은 다른 일이다.* 그리고 **`--why-slow` 를 안 봤으면
    이 파일은 그대로 실렸을 것이다.**

## 오라클

RFC 9112 예제(정상 8 자리) · **거절 9 건** · VM ≡ native · 그리고 **태그 경로 op 0**
(perf 게이트가 본다 — 파서가 해석기로 떨어지면 서버는 못 쓴다).
