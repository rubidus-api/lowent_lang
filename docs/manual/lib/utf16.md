# utf16 — UTF-16 서로게이트 산술

소스: `lib/utf16.low` · 검증: `impl/tests/vm_utf16.low`

## 처음 쓰는 사람에게

**무엇을 하는 모듈인가.** UTF-16 의 서로게이트 쌍을 코드포인트로 바꾸고 되돌린다.
낱말 둘만 먼저 풀면 — **코드포인트(code point)** 는 문자 하나에 붙은 유니코드 번호이고,
**서로게이트(surrogate)** 는 UTF-16 이 큰 문자를 두 칸에 나눠 담을 때 쓰는 짝이다(앞의
상위 칸과 뒤의 하위 칸이 **붙어야** 문자 하나다).

**언제 쓰나.** Windows API 나 UTF-16 로 오는 데이터를 다룰 때 쓴다.

**최소 예제.** 아래가 이 모듈을 쓰는 가장 짧은 꼴이다. 각 줄이 무엇을 하는지는 주석에 적었다.

```lowent
use utf16 .

rem s 는 slice u16 — 16비트 "칸(unit)" 이 죽 늘어선 것이 UTF-16 문자열이다.
let c option u64 . be utf16.decode s 0 .   rem 서로게이트 쌍이면 둘을 합쳐 하나로
guard is_some c . else return 1 .          rem 짝이 안 맞으면 none — 조용히 넘기지 않는다
```

여기서 `0` 은 "첫 글자" 가 아니라 **0 번 칸**이다. 이 모듈의 위치는 전부 칸 번호이고,
글자 단위 전진은 `next` 가 대신 해 준다(짝이면 두 칸을 뛴다).

**읽는 순서.** 급하면 «op 한눈에» 표만 봐도 된다. 왜 이렇게 생겼는지가 궁금하면 «왜 있는가»부터, 실제로 쓰다 막히면 «반례»와 «주의사항»을 먼저 보면 된다.

## 왜 있는가

이 절은 "왜 새 타입이 아니라 라이브러리인가" 와 "왜 UTF-16 에는 서로게이트가 있는가" 를
적는다. 요약하면: `slice u16` 이 이미 UTF-16 문자열이므로 언어는 늘릴 것이 없고, 남는
진짜 일은 두 칸으로 쪼개고 도로 합치는 산술뿐이다.

이 모듈은 UTF-16 텍스트를 다룰 때 쓴다 — Windows API·Java·JavaScript 처럼 문자열을
16비트 칸으로 드는 세계와 값을 주고받는 자리다. 낱말 둘을 먼저 풀면: **코드포인트**는
문자 하나에 붙은 유니코드 번호(예: '가' = U+AC00 = 44032)이고, **UTF-16** 은 그 번호를
16비트 칸(unit) 한 개 또는 두 개로 적는 방식이다.

**왜 서로게이트가 생겼는가.** UTF-16 은 처음에 "문자 하나 = 16비트 한 칸" 으로 모든 글자를
담으려 했다. 그런데 유니코드가 65,536 자를 넘어 자라면서 한 칸으로는 모자라게 됐다. 그래서
값 구간 U+D800–U+DFFF 를 **문자로 쓰지 않기로 비워 두고**, 그 구간의 두 칸을 조합해 큰
코드포인트를 표현하기로 했다. 상위 1024 가지 × 하위 1024 가지 = 1,048,576 가지, 딱
U+10000–U+10FFFF 를 덮는다. 이 두 칸짜리 조합이 **서로게이트 쌍(surrogate pair)** 이다.
그래서 UTF-16 에서는 **칸 하나를 읽는 것과 문자 하나를 읽는 것이 다르다** — 이 어긋남을
메우는 것이 이 모듈이다.

원래 요구(RFC-0068 S6)는 `u16str`/`u32str` 를 **언어 타입**으로 달라는 것이었다. 그런데 재
보니 **`slice u16`·`slice u32` 가 이미 빠짐없이 된다**(읽기·쓰기·인덱싱 전부). 리프 규칙이 묻는
두 질문 — ① capability 가 필요한가, ② 언어에 없는 표현이 필요한가 — 에 **둘 다 아니오**다.
순수 계산이고, `slice u16` 이 곧 그 표현이다. 편의는 자격이 아니다. 그래서 **새 타입 0 · 새
키워드 0 · 빌트인 op 0** — 언어가 아니라 라이브러리가 되었다.

남는 진짜 일은 하나뿐이다: **서로게이트 산술**. **서로게이트(surrogate)**란 U+D800–U+DFFF
로 예약된 값 구간이다 — 그 자체는 문자가 아니고, **BMP**(기본 다국어 평면: U+0000–U+FFFF,
한 칸으로 끝나는 구간) 밖(≥ U+10000)의 코드포인트를 **짝(surrogate pair)** 두 칸으로
쪼갤 때 쓰는 부품이다. UTF-16 이 UTF-8 과 다른 점은 딱 이것 하나이고, 그 산술과 그 실패
방식이 이 라이브러리의 전부다.

덧붙여 **UTF-32 라이브러리는 없다**: `slice u32` 의 한 칸이 곧 코드포인트라서, 필요한 것은
검증뿐이고 그것은 `cp_valid` 한 줄이다. 없는 일을 만들지 않는다.

## 설계 의도와 경계

이 절은 "틀린 입력에 무엇으로 답하는가" 와 "무엇을 일부러 안 짓는가" 를 적는다. 한 줄로:
**짝이 안 맞으면 `none`**, 그리고 그 거절이 이 라이브러리가 하는 일의 절반이다.

**하는 것** — 코드포인트 ↔ UTF-16 칸(unit) 변환과, 틀린 것의 거절:

- 짝 없는 상위 서로게이트(D800–DBFF 뒤에 하위가 안 옴) → `none`
- 짝 없는 하위 서로게이트(DC00–DFFF 가 혼자 옴) → `none`
- 범위 밖 코드포인트(> U+10FFFF) → `none`

이 거절은 `lib/utf8.low` 과 **짝이 맞는다**: utf8 이 UTF-8 안의 서로게이트를 거절하므로,
서로게이트는 **오직 UTF-16 안에서만, 오직 짝으로만** 존재한다. 두 라이브러리가 함께 그
불변을 지킨다.

**정직하게 안 하는 것**: 정규화(NFC/NFD) · 대소문자 · 조합 문자 · UTF-16 **바이트 순서**
(BOM·big/little — `slice u16` 은 이미 기계 순서다; 바이트로 오갈 일이 생기면 그때 답한다).

모든 op 는 `effects none` 이고 숨은 할당이 없다. **효과(effect)** 란 그 op 이 무슨 비용·권한을
쓰는지 시그니처에 적어 두는 표시다 — `effects none` 은 할당도, 입출력도, 전역 상태 변경도
없다는 뜻이라 fn·계약·comptime 어디서든 부를 수 있다. `put` 은 `proc` 이지만 이 역시
`effects none` 이다: 자기 상태가 아니라 **호출자가 건네준 버퍼**에만 쓰기 때문이다.

## 자료구조

새 struct 도 enum 도 없다. 이 절은 "칸이 어떻게 늘어서 있고, 두 칸짜리 문자가 어떤 산술로
쪼개지는가" 만 적는다 — 이것만 알면 «op 상세» 의 숫자들이 전부 설명된다.

새 자료구조는 없다. **`slice u16` 이 곧 UTF-16 문자열**이고, 한 원소가 한 칸(unit)이다.

- BMP(U+0000–U+FFFF, 서로게이트 구간 제외) 코드포인트 = **한 칸**, 값 그대로.
- U+10000–U+10FFFF = **두 칸**. `v = c − 0x10000` 으로 20비트를 만들고
  상위 칸 `hi = 0xD800 + v/1024`, 하위 칸 `lo = 0xDC00 + v%1024` 로 가른다
  (시프트 op 없이 `div`/`mod` 1024 — 부호 없는 정수에서 같다).
- 경계 상수(10진): 상위 서로게이트 55296–56319(D800–DBFF), 하위 56320–57343(DC00–DFFF),
  코드포인트 상한 1114111(U+10FFFF).
- 서로게이트 값 자체는 **코드포인트가 아니다** — UTF-16 의 부품일 뿐이다. `cp_valid` 가
  거절한다.

칸 하나를 집어 들었을 때 그것이 무엇인지는 값 범위만 보면 갈린다. 이 세 갈래가 `decode`
가 하는 판정의 전부다.

| 칸 값(10진) | 정체 | 뜻 |
|---|---|---|
| 55296–56319 | 상위 서로게이트 | 두 칸짜리 문자의 **앞** 조각 — 뒤에 하위가 와야 한다 |
| 56320–57343 | 하위 서로게이트 | 두 칸짜리 문자의 **뒤** 조각 — 혼자 오면 틀린 것이다 |
| 그 밖 | 평범한 BMP 칸 | 그 값이 곧 코드포인트다 |

되돌리는 산술은 쪼개기의 역이다: `c = 0x10000 + (hi − 0xD800) × 1024 + (lo − 0xDC00)`.
`decode` 가 그대로 이 식을 쓴다.

## op 한눈에

op 은 열하나다. **판별**(`is_high`·`is_low`·`cp_valid`), **쓰기 쪽**(`units`·`unit_hi`·
`unit_lo`·`put`), **읽기 쪽**(`decode`·`next`), **전체 훑기**(`count_chars`·`is_valid`) 로
갈린다. 실무에서 가장 많이 쓰는 것은 `put`(쓰기)과 `decode`+`next`(순회) 넷이다.

| op | 종류 | 시그니처 요약 | 실패 시 |
|---|---|---|---|
| `is_high` | fn | `u u64 → bool` | 실패 없음 |
| `is_low` | fn | `u u64 → bool` | 실패 없음 |
| `cp_valid` | fn | `c u64 → bool` | 실패 없음(거짓이 곧 답) |
| `units` | fn | `c u64 → u64` | 실패 없음(1 또는 2) |
| `unit_hi` | fn | `c u64 → option u64` | 유효하지 않은 코드포인트 = `none` |
| `unit_lo` | fn | `c u64 → option u64` | 무효 코드포인트·BMP(칸 하나) = `none` |
| `put` | proc | `dst mut slice u16, at u64, c u64 → option u64` (**다음 위치**) | 무효 코드포인트·자리 부족 = `none` |
| `decode` | fn | `s slice u16, at u64 → option u64` | 범위 밖·짝 안 맞음 = `none` |
| `next` | fn | `s slice u16, at u64 → option u64` | 끝·망가진 자리 = `none` |
| `count_chars` | fn | `s slice u16 → option u64` | 망가진 자리 발견 = `none` |
| `is_valid` | fn | `s slice u16 → bool` | 실패 없음 |

## op 상세

op 하나하나를 본다. 매개변수마다 "왜 이것을 받는가" 를 한 줄로 붙였다 — 이 모듈은 아무
상태도 안 들고 있으므로 버퍼도, 위치도, 전부 호출자가 준다.

- `is_high u` / `is_low u` — `u` 가 상위(D800–DBFF)/하위(DC00–DFFF) 서로게이트 값인가.
  단순 범위 검사다. 슬라이스에서 읽은 칸이 짝의 앞쪽인지 뒤쪽인지 가릴 때 쓴다.
  - `u` — 검사할 **칸 하나**의 값. 왜 슬라이스가 아닌가: 이 판정에는 앞뒤 문맥이 필요
    없다. 값 범위만으로 끝난다.
- `cp_valid c` — `c` 가 코드포인트로서 유효한가. `c > 1114111` 이거나 서로게이트
  구간(55296–57343)이면 `false`.
  - `c` — 검사할 코드포인트 후보. 왜 필요한가: 바깥에서 들어온 수가 정말 문자 번호인지
    아무도 보장해 주지 않는다. 쓰기 전에 한 번 거르는 문이 여기다.
- `units c` — 코드포인트 하나가 먹는 칸 수. `c ≥ 65536` 이면 2, 아니면 1. 버퍼 크기를
  미리 셈할 때 쓴다. **유효성 검사를 하지 않는다** — 유효성은 `cp_valid`/`put` 의 몫이다.
  - `c` — 칸 수를 물을 코드포인트. 왜: 필요한 자리 수는 값의 크기에만 달렸다(65536 이
    유일한 경계다).
- `unit_hi c` — 상위 칸. BMP 면 `some c`(그 자체가 답). 2칸이면 `some (0xD800 + v/1024)`.
  `cp_valid` 가 아니면 `none`.
  - `c` — 쪼갤 코드포인트. 왜: 상위 칸은 `c` 의 위쪽 비트에서만 나온다.
- `unit_lo c` — 하위 칸. BMP 면 `none` — 여기서 `none` 은 오류가 아니라 "칸이 하나뿐"을
  뜻한다. 2칸이면 `some (0xDC00 + v%1024)`. 무효 코드포인트도 `none`.
  - `c` — 쪼갤 코드포인트. 왜: 하위 칸은 `c` 의 아래쪽 10비트에서 나온다. 그래서 `c` 가
    작으면(BMP) 애초에 하위 칸이 존재하지 않는다.
- `put dst at c` — 코드포인트를 `dst` 의 `at` 부터 실제로 써 넣는다. 반환은 **다음에 쓸 위치**
  (`some (at+1)` 또는 `some (at+2)`).
  ★ **2026-08-15 에 바뀌었다**: 전에는 **쓴 칸 수**(1 또는 2)를 돌려줬다. 이 모듈의 `decode`·`next`
  는 위치 축이라, 둘을 함께 쓰는 코드가 답을 위치로 알고 더하지 않으면 **조용히 틀렸다** —
  `prog/enc.low` 의 첫 판이 실제로 그렇게 틀렸다. 이제 축이 하나다. 몇 칸 썼는지가 필요하면
  `units c` 가 이미 답한다. `cp_valid` 가 아니거나 `at + units c > len dst` 면 `none` 이고,
  이때 **한 칸도 안 쓴다**(전량-아니면-무 — `lib/strbuf.low` 의 규율).
  - `dst` — **호출자 버퍼**(호출자가 미리 잡아 건네준 쓰기 대상). 왜 받는가: 이 모듈은
    스스로 메모리를 만들지 않는다(숨은 할당 없음 = `effects none`). 그러니 쓸 자리는
    반드시 밖에서 받아야 하고, 그 통로가 이 매개변수다.
  - `at` — 어느 칸부터 쓸 것인가. 왜 받는가: 버퍼는 호출자의 것이라 어디에 쓸지도 호출자가
    정한다. 여러 문자를 이어 쓸 때는 앞 호출이 돌려준 칸 수(1 또는 2)만큼 전진시킨다.
  - `c` — 써 넣을 코드포인트. 왜: 쪼갤지 말지, 몇 칸을 먹을지가 이 값 하나로 정해진다.
  - 반환값을 왜 칸 수로 주는가: 다음 `at` 을 호출자가 계산할 수 있게 하려는 것이다. 이
    값을 더해 가면 `units` 를 따로 부를 필요가 없다.
- `decode s at` — `s` 의 `at` 에서 코드포인트 하나를 읽는다. 평범한 BMP 칸이면 그 값,
  상위 서로게이트면 바로 다음 칸이 하위인지 확인하고 합친다. `none` 이 되는 경우:
  `at ≥ len s` · 하위가 혼자 옴 · 상위 뒤에 하위가 안 옴 · 상위로 끝남(잘림).
  - `s` — 읽을 칸 배열 전체. 왜 칸 하나가 아닌가: 짝은 **두 칸**이라 뒤 칸까지 볼 수 있어야
    하고, `len s` 가 곧 "잘렸는가" 의 판정 근거다.
  - `at` — 어디서부터 읽는가. 왜 받는가: 이 모듈은 커서를 안 들고 있다 — 순회 상태는
    호출자의 것이다. 그래서 `effects none` 이고 재진입이 공짜다. 값은 문자의 **시작**
    칸이어야 한다(짝의 하위 칸을 가리키면 `none`).
- `next s at` — 다음 코드포인트의 자리. `decode` 가 성공해야 하고, 상위 서로게이트에서
  시작했으면 `some (at+2)`, 아니면 `some (at+1)`. 끝이거나 망가졌으면 `none`. 순회의
  전진 걸음이다 — 짝을 두 칸으로 건너뛰는 셈을 호출자가 직접 하지 않게 해 준다.
  - `s` — 읽을 칸 배열 전체. 왜: 안쪽에서 `decode` 를 부르므로 같은 것이 필요하다.
  - `at` — 지금 문자의 시작 칸. 왜: "다음" 은 지금이 어디인지 알아야 정해지고, 지금 칸이
    상위 서로게이트인지에 따라 걸음이 1 이 아니라 2 가 된다.
- `count_chars s` — 전체를 훑어 코드포인트 수를 센다. 망가진 자리를 만나면 **수를 안
  낸다**(`none`) — 틀린 수를 내느니 안 낸다.
  - `s` — 셀 대상 전체. 왜 시작 위치를 안 받는가: "전체" 가 계약이다. 일부만 세려면
    호출자가 `subslice` 로 잘라서 준다(단, 짝 한가운데서 자르면 안 된다).
  - 비용은 O(칸 수)다. 훑는 김에 검증까지 하므로 `is_valid` 와 같은 값을 치른다.
- `is_valid s` — `count_chars` 가 `some` 인가.
  - `s` — 검사할 칸 배열 전체. 왜: 유효성은 부분으로 나눠 물을 수 없다 — 짝의 반쪽만
    떼어 보면 그 자체로는 무효로 보인다.

## 사용법과 예제

기본 흐름은 두 가지다. 쓰기는 "`put` 을 부르고 → 돌려받은 칸 수만큼 자리를 민다", 읽기는
"`decode` 로 값을 읽고 → `next` 로 전진한다". 어느 쪽이든 커서는 호출자가 든다.

std 라이브러리는 from-생략 `use` 로 해소되고, 짧은 별칭이 관례다.

```lowent
module ex_utf16 .

use utf16 as u .

rem 왕복 — 써 넣고 다시 읽으면 같은 코드포인트. 성공 = 42.
proc round_trip output u64 . input buf mut slice u16 . . effects none . do
  guard ge (len buf) 4 . else return 90 .          rem 버퍼는 호출자 것 — 자리부터 확인한다
  rem '가'(U+AC00) — BMP 라서 한 칸. put 이 쓴 칸 수를 돌려준다.
  let a option u64 . be u.put buf 0 44032 .        rem 0 번 칸에 쓴다
  guard is_some a . else return 1 .                rem 무효 코드포인트·자리 부족이면 none
  guard eq (some_value a) 1 . else return 2 .      rem 쓴 칸 수 = 1 → 다음 자리는 0+1 = 1

  rem U+1F4A9 이모지 — BMP 밖이라 두 칸(서로게이트 짝)으로 갈라진다.
  let b option u64 . be u.put buf 1 128169 .       rem 앞 호출이 준 1 번 칸부터 이어 쓴다
  guard is_some b . else return 3 .
  guard eq (some_value b) 2 . else return 4 .      rem 쓴 칸 수 = 2 → 칸 1 과 2 를 먹었다
  guard eq (index buf 1) 55357 . else return 5 .   rem 0xD83D — 상위 칸
  guard eq (index buf 2) 56489 . else return 6 .   rem 0xDCA9 — 하위 칸

  rem 다시 하나로 읽는다 — decode 가 짝을 도로 합친다.
  let rb option u64 . be u.decode buf 1 .          rem 짝의 시작(상위) 칸을 가리켜야 한다
  guard is_some rb . else return 7 .
  guard eq (some_value rb) 128169 . else return 8 . rem 쪼갠 것이 그대로 되돌아왔다

  rem 전체 세기: 'A' + 이모지(짝) + '가' = 칸 넷, 문자 셋 — 칸 수 ≠ 문자 수다.
  set (index buf 0) 65 .                           rem 'A' 로 덮어쓴다(BMP 한 칸)
  set (index buf 3) 44032 .                        rem 마지막 칸에 '가'
  let n option u64 . be u.count_chars (subslice buf 0 4) .
  guard is_some n . else return 9 .                rem none 이면 짝이 깨진 것이다
  guard eq (some_value n) 3 . else return 10 .     rem len 은 4 인데 문자 수는 3
  return 42 .
end
```

순회는 `next` 로 한다. 한 바퀴가 어떻게 도는지 주석으로 짚으면 이렇다.

```lowent
var i u64 be 0 .                          rem 커서 — 문자 번호가 아니라 칸 번호다
while lt i (len s) . do
  rem ── 한 바퀴: i 에서 값을 읽고 → i 를 다음 문자로 옮긴다 ──
  let c option u64 . be u.decode s i .    rem ① i 에서 문자 하나(짝이면 두 칸을 합쳐서)
  guard is_some c . else return 80 .      rem   짝이 깨졌으면 여기서 빠진다
  rem … some_value c 로 코드포인트를 쓴다 …
  let nx option u64 . be u.next s i .     rem ② 다음 문자의 시작 칸
  guard is_some nx . else return 81 .
  set i (some_value nx) .                 rem   BMP 면 +1, 짝이면 +2 — 직접 세지 않는다
end
```

어느 쪽이든 `none` 이면 멈춘다(끝 또는 망가짐 — `is_valid` 를 먼저 재면 구분된다).

## 반례 — 이렇게 쓰면 안 된다

실제로 자주 밟는 잘못된 코드들이다. 각 줄에 **증상**을 적었다 — 이 모듈의 실패는 거의 전부
`none`(값으로 오는 거절)이고, 트랩은 그 `none` 을 검사 없이 `some_value` 로 꺼낼 때 비로소
난다.

```lowent
rem ✗ ⓐ 짝 없는 서로게이트를 decode 로 통과시키려 한다 — 안 된다. 증상: none.
set (index buf 0) 55357 .          rem 상위 0xD83D
set (index buf 1) 65 .             rem 뒤에 'A' — 하위가 아니다
let a option u64 . be u.decode buf 0 .    rem → none

rem ✗ ⓑ 하위 서로게이트가 혼자 온다. 증상: none.
set (index buf 2) 56489 .
let b option u64 . be u.decode buf 2 .    rem → none

rem ✗ ⓒ 상위 서로게이트로 끝난다(잘렸다). 증상: none.
set (index buf 3) 55357 .
let c option u64 . be u.decode (subslice buf 0 4) 3 .   rem → none

rem ✗ ⓓ 두 칸짜리를 마지막 한 칸에 넣으려 한다. 증상: none — 그 칸은 안 더럽혀진다.
let last u64 be sub (len buf) 1 .
let r option u64 . be u.put buf last 128169 .           rem → none, buf[last] 그대로

rem ✗ ⓔ 서로게이트 값을 코드포인트로 쓰려 한다. 증상: cp_valid = false, put 도 none.
u.cp_valid 55357                   rem → false
```

증상을 알아채는 법을 한 줄씩 덧붙이면: ⓐⓑⓒ 는 **`decode`/`next` 가 `none`** 을 내므로
`guard is_some …` 자리에서 바로 걸린다 — 전체가 성한지 미리 알고 싶으면 `is_valid` 를
한 번 재면 된다(`false`). ⓓ 는 **`put` 이 `none`** 이고, 버퍼는 **한 칸도 안 바뀐다** —
"반쯤 쓰다 말았나" 를 걱정하지 않아도 된다는 뜻이다. ⓔ 는 **`cp_valid` 가 `false`** 라
`put`·`unit_hi`·`unit_lo` 가 전부 `none` 이 된다.

그리고 이 `none` 들을 검사 없이 `some_value` 로 꺼내면 증상이 바뀐다 — 실행 중
**E-VM-NONE 트랩(패닉)** 으로 멈춘다. 컴파일은 통과하므로 `guard` 가 먼저다.

셋 다(ⓐⓑⓒ) 조용히 통과시키면 그 뒤의 모든 것이 틀린다 — **거절이 곧 이 라이브러리의
값**이다. 그리고 온전한 짝은 여전히 통과한다: 거절이 과하지 않다.

## 주의사항

여기 있는 함정은 거의 전부 **"칸 수 ≠ 문자 수"** 한 문장에서 나온다. 아래를 한 번씩
자문해 보면 대부분 걸러진다.

- **`len s` 는 칸 수다, 문자 수가 아니다.** 문자 수는 `count_chars` 만이 안다. 이모지 하나가
  칸 둘을 먹으므로 "최대 10 글자" 를 `len` 으로 재면 어긋난다.
- **짝 한가운데서 자르지 마라.** `subslice` 로 상위와 하위 사이를 가르면 양쪽 조각이 다
  무효가 된다(앞은 "상위로 끝남", 뒤는 "하위가 혼자 옴"). 자를 자리는 `next` 가 준 값이어야
  한다.
- **커서는 `add i 1` 이 아니라 `next` 로 민다.** 1 씩 밀면 짝의 하위 칸을 문자 시작으로
  읽게 되어 `none` 이 나오거나, 문자 수가 부풀어 오른다.
- `decode`/`next`/`put` 은 O(1), `count_chars`/`is_valid` 는 O(칸 수)다. 길이를 자주 물을
  거면 한 번 세어 들고 다녀라(루프 조건 안에서 매번 부르면 전체가 O(n²)가 된다).
- 모든 op 가 `effects none` 이고 스크래치가 없다 — **재진입은 공짜**다.
- `units` 는 유효성을 안 본다. "몇 칸 필요한가"만 답한다. 무효 코드포인트를 걸러야 하면
  `cp_valid` 를 먼저 묻거나, 어차피 거절하는 `put` 에 맡겨라.
- `unit_lo` 의 `none` 은 두 뜻이 겹친다(무효 코드포인트 / BMP). 구분이 필요하면 `cp_valid`
  를 먼저 물어라. 조합해 쓸 때는 `put` 이 낫다 — 실패가 `none` 하나로 정리된다.
- 바이트 직렬화(BOM·엔디안)는 이 라이브러리 밖이다. `slice u16` 은 기계 순서다. 파일이나
  네트워크에서 온 **바이트**를 `slice u16` 으로 만드는 일은 호출자 몫이다.
- UTF-8 쪽 이야기는 [`utf8`](utf8.md) 에 있다. 두 모듈은 서로게이트를 두고 짝을 이룬다 —
  UTF-8 안에 서로게이트는 없고, UTF-16 안에서는 반드시 짝으로만 있다.
