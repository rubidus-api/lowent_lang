## ② 하나씩 — 예제와 함께

### 1. 집합과 관계

**집합**은 그냥 모음이다. `{0, 1, 2}`. **관계**는 "짝 목록" 이다. 예컨대 "작다" 관계는
`{(0,1), (0,2), (1,2)}` 처럼 순서쌍의 모음이다.

프로그램 얘기에서는 이렇게 쓴다:

- 타입의 집합: `{u8, u16, u32, u64, i8, …}`
- "안전하게 확대된다" 관계: `u8 ⊑ u16`, `u8 ⊑ u32`, …

기호 `⊑` 는 "**⊑ 의 왼쪽이 오른쪽에 안전하게 들어간다**" 로 읽는다. 부등호 `≤` 와 비슷하게
생겼지만 수의 크기가 아니라 **담을 수 있는가**를 말한다.

### 2. 부분 순서 — 비교 못 하는 쌍이 있어도 되는 순서

수는 늘 비교된다: 3 과 5 중 하나가 크다. 그런데 타입은 그렇지 않다.

```
u8 ⊑ u16 ⊑ u32 ⊑ u64      (부호 없는 정수: 폭이 커지면 안전)
i8 ⊑ i16 ⊑ i32 ⊑ i64      (부호 있는 정수도 마찬가지)

u32 와 i32 는?  → **비교 불가**
```

왜 비교 불가인가? `u32` 는 40억까지 담고 `i32` 는 음수를 담는다. 어느 쪽도 상대를 다 담지 못한다.
**어느 쪽이 크다고 말할 수 없다** — 그리고 그것을 정직하게 표현하는 것이 부분 순서다.

부분 순서가 되려면 세 조건을 만족해야 한다. 이름은 어렵지만 뜻은 당연하다:

| 조건 | 뜻 | 예 |
|---|---|---|
| **반사성** | 자기 자신에는 항상 들어간다 | `u8 ⊑ u8` |
| **추이성** | 징검다리로 이어진다 | `u8 ⊑ u16` 이고 `u16 ⊑ u32` 면 `u8 ⊑ u32` |
| **반대칭성** | 서로 들어가면 같은 것이다 | `A ⊑ B` 이고 `B ⊑ A` 면 `A = B` |

이 셋이 **증명되어야** 한다. 안 그러면 "안전한 확대" 라는 말이 뜻을 잃는다. 예컨대 추이성이
깨지면, 컴파일러가 `u8 → u16` 을 허용하고 `u16 → u32` 를 허용하는데 `u8 → u32` 는 막는 이상한
언어가 된다. Lowent 는 이 셋을 Coq 으로 증명했다(03장).

### 3. 격자와 join — 두 개를 합칠 때 무엇을 고르나

이런 코드를 생각해 보자.

```lowent
if cond . do  set x a .  end      rem a 는 u8
if cond . do  set x b .  end      rem b 는 u16
rem 여기서 x 의 타입은?
```

두 갈래가 합쳐지는 자리에서 컴파일러는 **둘을 다 담는 타입**을 골라야 한다. 후보는 여럿이다
(`u16`, `u32`, `u64` 모두 둘을 담는다). 그중 **가장 작은 것**을 고르는 게 맞다 — 필요 이상으로
크게 잡으면 비용이 늘어난다.

그 "가장 작은 공통 상위" 를 **join**(⊔)이라 부른다.

```
u8 ⊔ u16 = u16          (둘을 다 담는 가장 작은 타입)
u8 ⊔ i8  = i16          (u8 은 255까지, i8 은 −128까지 → 둘을 담으려면 i16 이 필요하다)
```

두 번째 예가 중요하다. **직관과 다르다** — 폭이 같은데 결과가 더 넓어진다. 이런 자리에서 사람은
틀리고, 그래서 기계로 증명한다: *"두 타입의 join 은 둘 다를 안전히 담는다"*(`join_sound`).

부분 순서에서 임의의 두 원소가 항상 join 을 가지면 그 구조를 **격자**라 부른다.

### 4. 단조 함수와 고정점 — 루프는 왜 멈추는가

**단조 함수**란 "입력이 커지면 출력도 작아지지 않는" 함수다. `f(x) = x + 1` 은 단조다.

**고정점**은 `f(x) = x` 인 점이다. 즉 **한 번 더 적용해도 변하지 않는** 점.

컴파일러가 루프를 분석할 때 이런 일이 벌어진다:

```lowent
var i u64 be 0 .
while lt i 10 . do
  set i (add i 1) .
end
```

분석기는 "루프에 들어올 때 i 의 범위" 를 모른다. 그래서 **모르는 상태에서 시작해 반복해서
넓힌다**:

```
1회전 후: i ∈ [0, 0]        (처음엔 0 만 가능)
2회전 후: i ∈ [0, 1]        (0 이거나 1)
3회전 후: i ∈ [0, 2]
…
```

이대로면 영원히 끝나지 않는다. 그래서 **위드닝**(widening)을 쓴다: 몇 번 넓어지는 걸 보면
"아, 계속 커지겠구나" 하고 한 번에 위쪽 끝까지 밀어 버린다.

```
위드닝 후: i ∈ [0, ∞)      → 여기에 루프 조건 i < 10 을 합치면 i ∈ [0, 9]
```

이제 한 번 더 돌려도 `[0, 9]` 다 — **고정점에 도달했다**. 분석이 끝난다.

요점 둘:
- **고정점은 분석이 끝나는 지점**이다. 고정점이 항상 존재한다는 것이 분석이 **멈춘다**는 보장이다.
- 위드닝은 **더 넓게** 잡는다. 즉 실제보다 크게 잡을 수 있다 — 그러면 검사를 못 없앨 뿐,
  **틀린 답은 안 나온다**. 이 방향성이 다음 항목의 핵심이다.

### 5. 귀납법과 불변식 — 도미노

수학적 귀납법을 기억할 것이다:

```
P(0) 이 참이다.
P(n) 이 참이면 P(n+1) 도 참이다.
──────────────────────────
모든 n 에 대해 P(n) 이 참이다.
```

프로그램에서는 n 이 "실행 걸음 수" 가 된다. 그리고 P 를 **불변식**(invariant)이라 부른다 —
"실행 내내 참인 성질".

Lowent 의 중심 정리가 정확히 이 모양이다(06장):

```
시작할 때 차용 상태는 깨끗하다.                          ← P(0)
정적 검사를 통과한 이벤트를 하나 실행하면
   깨끗한 상태는 여전히 깨끗하다.                        ← P(n) → P(n+1)
─────────────────────────────────────────────
따라서 **몇 걸음을 실행해도** 차용 위반이 없다.           ← ∀n, P(n)
```

이 논증의 좋은 점: **몇 걸음인지 몰라도 된다**. 그래서 루프를 몇 번 도는지 몰라도 결론이 선다
(07장이 그 이야기다).

### 6. 추상해석 — 값 대신 범위로 계산하기

프로그램을 **돌리지 않고** 값에 대해 뭔가 알아내려면, 값 하나 대신 **값의 집합**을 다뤄야 한다.
집합을 그대로 다루면 너무 크니, 간단한 근사를 쓴다 — 예컨대 **구간** `[lo, hi]`.

```
x ∈ [0, 5],  y ∈ [10, 20]  이면
x + y ∈ [10, 25]           ← 양 끝만 더하면 된다
x * y ∈ [0, 100]
```

이렇게 "실제 값" 을 "구간" 으로 바꿔 계산하는 것을 **추상해석**이라 한다. 규칙은 하나다.

> **건전성(soundness) 방향**: 추상 계산의 결과는 **실제로 가능한 모든 값을 포함**해야 한다.
> 넓게 잡는 건 괜찮다(손해만 본다). **좁게 잡으면 틀린다**(위험하다).

예를 보자. 실제로 `x` 가 항상 3 인데 분석이 `[0, 5]` 라고 답했다 → 손해는 있지만 **안전하다**
(검사를 못 없앤다). 반대로 실제로 `x` 가 7 일 수 있는데 분석이 `[0, 5]` 라고 답했다 →
검사를 없애면 **범위 밖 접근이 일어난다**. 그래서 분석의 모든 규칙은 "넓게" 쪽으로 틀어져 있다.

## ③ 기호 표

뒷장에서 나오는 기호는 이것뿐이다. 헷갈리면 여기로 돌아오면 된다.

| 기호 | 읽는 법 | 뜻 |
|---|---|---|
| `A ⊑ B` | "A 는 B 에 안전히 들어간다" | 안전 확대 관계 |
| `A ⊔ B` | "A 와 B 의 join" | 둘을 다 담는 가장 작은 것 |
| `[lo, hi]` | "구간" | lo 이상 hi 이하의 값 |
| `∀x, P(x)` | "모든 x 에 대해 P" | 예외 없음 |
| `∃x, P(x)` | "어떤 x 가 있어 P" | 하나라도 있음 |
| `P → Q` | "P 면 Q" | 함의 |
| `⊤` (top) | "모름" | 아무 값이나 가능 |
| `x^k` | "x 를 k 번 이어붙임" | 루프 본문 k 회전 |

## ④ 이 도구들이 서로 어떻게 맞물리나

한 그림으로:

```
   부분 순서 ⊑          ← "안전하게 담긴다" 를 정의한다        (03장)
        │
        ├─ join ⊔       ← 갈래가 합칠 때 타입을 고른다         (03·08장)
        │
   격자 위의 단조 함수  ← 루프 분석이 이 위를 오른다           (04장)
        │
     고정점             ← 분석이 멈추는 지점                    (04·07장)
        │
   추상해석의 건전성    ← "넓게" 방향이면 결론이 안전하다       (04·05장)
        │
   불변식 + 귀납법      ← 실행 내내 유지됨을 보인다            (06·07·09장)
```

아래에서 위로 읽어도 된다: **귀납법으로 불변식을 지키고**, 그 불변식이 **추상해석의 건전성**에서
오고, 추상해석은 **격자** 위에서 돌고, 격자는 **부분 순서** 위에 세워진다.

## ⑤ 이것이 막는 버그 — 도구가 없으면 무엇이 새는가

수학 도구 자체가 버그를 막는 건 아니다. 그러나 **도구가 없으면 언어 설계가 어림짐작이 된다.**
실제로 이 저장소에서 있었던 일:

- **join 을 손으로 정한 표** → `u8 ⊔ i8` 을 `i8` 로 적을 위험. 그러면 255 가 −1 로 조용히 바뀐다.
  격자로 세우고 `join_sound` 를 증명하니 그런 표를 쓸 수가 없다(03장).
- **위드닝 없는 루프 분석** → 분석기가 안 끝난다(컴파일이 멈추지 않는다). 고정점 개념이
  "언제 끝나는가" 에 답한다(04장).
- **불변식 없는 차용 검사** → "이 경우엔 되고 저 경우엔 안 되는" 규칙 더미가 된다. 실제로
  `f r` 처럼 op 을 통과한 차용을 검사기가 **알아보지 못했다** — 불변식으로 다시 세우자 그 구멍이
  정리의 반례로 드러났다(06장).

## ⑥ 증명하지 않은 것 (이 장에서)

이 장은 **어휘를 소개**했을 뿐 아무것도 증명하지 않았다. 위에 적은 성질들(반사성·추이성·
반대칭성·join 건전성·고정점 존재)이 **Lowent 의 실제 정의에 대해** 성립한다는 것이 03장부터의
내용이다.

또한 정직하게: 추상해석의 건전성은 **"규칙이 넓게 잡는다"** 를 규칙마다 확인해야 한다.
한 규칙이라도 좁게 잡으면 그 자리에서 새어 나간다. 그래서 04·05장에서는 규칙 하나하나에 대해
"왜 이건 넓은가" 를 적는다.
