# 09. 데이터 경합 자유 — 규율이 메모리 모델을 대신한다

> **근거**: `LowentDRF.v` — `l1_no_race`(Qed) · `l1_condition_is_necessary`(Qed) ·
> `l2_accesses_are_separated_by_a_message`(Qed).

## ① 5분 요약

두 스레드가 **같은 자리를 동시에** 만지고 그중 하나가 쓰기면 — 그것이 **데이터 경합**이다.
경합이 있으면 무슨 값이 나올지 아무도 모른다. C/C++ 에서는 아예 **정의되지 않은 동작**이다.

경합을 다루는 보통의 길은 **메모리 모델**을 배우는 것이다(acquire·release·fence…). 어렵다.

이 장의 주장은 다르다:

> **level 1·2 코드는 메모리 모델을 볼 일이 없다.** 경합이 **규율에 의해** 원천 차단되므로.

그리고 그 주장은 **순수 Coq 으로 증명된다.** RC11 도 Iris 도 필요 없었다.

## ② 필요한 수학

### Bernstein 조건 — 1966년의 답

두 태스크가 **읽는 자리 집합**과 **쓰는 자리 집합**을 각각 R·W 라 하자. 두 태스크가
**독립(independent)** 이라는 것은:

```
W₁ ∩ W₂ = ∅        둘이 같은 자리에 쓰지 않는다
W₁ ∩ R₂ = ∅        하나가 쓰는 자리를 다른 하나가 읽지 않는다
R₁ ∩ W₂ = ∅        그 반대도 아니다
```

**집합의 교집합이 비었다**는 세 줄이 전부다. 고등학교 집합론이다. (R₁ ∩ R₂ 는 조건에 없다 —
둘이 같은 자리를 **읽는 것은 괜찮다.**)

### 경합의 정의

```
경합(t₁, t₂, l)  ⟺  t₁ 이 l 을 건드린다 ∧ t₂ 도 건드린다 ∧ 적어도 하나는 쓰기
```

보통의 정의에는 "그리고 두 접근이 **happens-before 로 순서지어지지 않았다**" 가 붙는다.
level 1 에서는 그 조건이 **자동으로 만족**된다 — fork 이후 join 전까지 태스크들 사이에는
hb 간선이 아예 없기 때문이다. 그래서 남는 것이 위의 세 조건뿐이다.

## ③ 정리와 그 뜻

### 정리 C1 — level 1: 독립이면 경합이 없다

> **Coq 원문**: `Theorem l1_no_race : forall t1 t2 l, indep t1 t2 -> ~ races t1 t2 l.`

> **평서문**: 두 태스크가 Bernstein 독립이면, **어떤 자리에서도** 경합하지 않는다.

증명은 다섯 줄이다. 경합이 있다고 가정하면 "하나가 쓴다" 는데, 독립 조건이 그 자리에 대한
상대의 접근을 **세 경우 모두** 부정한다. 모순.

이 다섯 줄이 왜 값진가? "level 1 병렬은 메모리 모델이 안 보인다" 는 설계 주장의 **전부**가
여기 있기 때문이다. 경합이 없으면 **DRF-SC 정리가 발동해** 프로그램이 순차 일관성(SC)처럼
행동한다 — 즉 순서를 뒤죽박죽으로 상상할 필요가 없다.

**막는 버그**: 병렬로 나눈 두 조각이 같은 배열 칸을 건드리는 것. 이 언어의 disjoint split 이
그것을 애초에 못 쓰게 한다.

### 정리 C2 — 그 조건이 **필요**하다

> **Coq 원문**: `Theorem l1_condition_is_necessary : ~ indep writer reader /\ races writer reader 0.`

> **평서문**: 조건을 어기는 짝(하나는 자리 0에 쓰고 하나는 자리 0을 읽는다)을 실제로 만들면
> **경합이 존재한다.**

이것이 정직한 증명의 표식이다. "조건을 만족하면 안전하다" 만 증명하면 조건이 **과하게
엄격**해도 정리는 참이다(아무것도 통과하지 않는 조건도 안전하다!). 그래서 **반례를 함께**
증명한다 — 조건을 느슨하게 하면 정말로 깨진다는 것.

> **정리 하나에 반례 하나.** 이 저장소가 여러 곳에서 쓰는 방식이다.

### 정리 C3 — level 2: 액터 사이에는 반드시 메시지가 있다

> **Coq 원문**:
> ```coq
> Theorem l2_accesses_are_separated_by_a_message :
>   forall o tr1 t1 w1 tr2 t2 w2 tr3 l,
>     wf o (tr1 ++ Access t1 l w1 :: tr2 ++ Access t2 l w2 :: tr3) ->
>     t1 <> t2 -> has_send l tr2 = true.
> ```

> **평서문**: 실행 흔적에서 **서로 다른** 액터가 같은 자리 `l` 을 접근한다면, 그 두 접근
> **사이에** 그 자리의 소유권을 넘기는 **메시지가 반드시 있다.**

논증의 사슬:

```
한 자리는 정확히 한 액터가 소유한다.          ← 모델의 규율(wf)
소유자만 접근한다.                             ← 같은 규율
소유권은 메시지로만 옮겨진다.                  ← 같은 규율
그런데 두 접근의 액터가 다르다.
──────────────────────────────────
따라서 그 사이에 소유권 이전(메시지)이 있었다.
메시지는 happens-before 간선이다.
hb 로 순서지어진 두 접근은 **정의상 경합이 아니다.**   ∎
```

**막는 버그**: 액터 모형에서 가장 흔한 실수 — 메시지로 **참조를 보내고 보낸 쪽도 계속 쓰는**
것. 소유권 이전으로 만들었으므로 보낸 쪽은 그 자리를 잃는다.

## ④ 증명의 전략 — 그리고 "가둠"

이 파일의 큰 그림은 **가둠(containment)** 이다.

```
level 1 (disjoint 병렬)  ─┐
level 2 (액터 격리)       ─┤→  경합이 **규율로** 없다  →  DRF-SC  →  SC 로 사고
level 3 (원자·락)         ─┘→  경합이 **실제로 있다**  →  메모리 모델이 필요(11·12장)
```

처음 계획은 *"안전 코드가 race-free 라는 명제는 스케치로 두고, 기계 증명은 iGPS/Cosmo 같은 무거운 도구로"*
였다. 그런데 다시 보니 **그 명제는 메모리 모델에 대한 주장이 아니었다.**
"규율이 경합을 막는다" 는 **집합론**의 주장이다. 무거운 도구가 필요한 곳은 level 3 뿐이다.

이것은 증명에서 거듭 나오는 패턴이다: **명제를 정확히 읽으면 필요한 도구가 줄어든다.**
"동시성이니까 분리논리가 필요하다" 는 반사적 판단이 틀렸다.

## ⑤ 이것이 막는 버그

```lowent
rem ① 겹치는 분할로 병렬 — 규율 위반
rem   두 태스크가 같은 칸을 쓰면 disjoint split 이 아니다 → 병렬 구성 자체가 거절된다

rem ② 액터가 보낸 것을 계속 쓴다
rem   send 로 소유권을 넘긴 뒤 그 자리를 접근하면 — 소유자가 아니므로 막힌다
rem   (06장 차용 규칙의 동시성 판이다: "한 자리를 고칠 수 있는 이름은 하나")
```

06장과의 연결이 요점이다. **배타성 규칙이 동시성에서 배당금을 준다.** 단일 스레드에서
"한 번에 하나" 를 강제해 두면, 그 규칙이 그대로 "두 태스크가 겹치지 않음" 이 된다.
안전 규칙 하나가 두 곳에서 값을 낸다.

## ⑥ 증명하지 않은 것

1. **DRF-SC 정리 자체는 인용이다.** "경합이 없으면 SC 처럼 행동한다" 는 널리 알려진 정리
   (Adve–Hill)이고, 이 저장소가 증명하지 않았다. 여기서 증명한 것은 **그 정리의 전제**
   (경합 없음)를 우리 규율이 만족한다는 것.
2. **RC11 의 내부는 여기 없다**(5 ordering·hb 폐포). 11장이 그 일부를 다루고, 전체는
   iGPS/Cosmo 급 작업이다.
3. **level 1·2 는 아직 구현되지 않았다**(MVP 제외). 그러므로 이 파일은 구현을 검증하지 않는다 —
   **구현이 지켜야 할 조건**을 정리로 못 박은 것이다. 구현이 오면 이 조건을 검사하면 된다.
   이것도 값이 있다: 조건을 나중에 발명하면 구현에 맞춰 느슨해진다.
4. **모델은 정적 R/W 집합을 가정한다.** 태스크의 읽기·쓰기 자리를 미리 안다고 가정하는데,
   포인터를 쓰면 그게 어렵다. 실제로는 타입 체계가 그것을 보장해야 한다.
