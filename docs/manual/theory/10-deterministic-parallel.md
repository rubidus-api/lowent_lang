# 10. 결정론 병렬 — 병렬 결과가 순차와 **비트까지** 같다

> **근거**: `LowentPar.v` — `det1_par_eq_seq`·`det1_bit_identical`·`overlap_is_nondeterministic`
> ·`det2_schedule_free`·`assoc_shape_free`·`nonassoc_shape_matters` (전부 Qed).
> UNPROVEN R2 의 "가정" 이 이 파일로 **정리가 됐다**.

## ① 5분 요약

경합이 없다고(09장) 끝이 아니다. 병렬 프로그램이 **매번 같은 답**을 내는가는 별개 문제다.

```
같은 입력으로 두 번 돌렸는데 답이 다르다.
```

이것은 경합이 없어도 일어난다. 예: 부동소수 덧셈을 여러 코어가 나눠 더한 뒤 합칠 때,
합치는 **순서**가 달라지면 마지막 비트가 달라진다. 경합은 없다(각자 자기 몫만 만졌다).
그런데 답이 다르다.

이 언어의 주장은 강하다:

> **level 1 병렬의 결과는 순차 실행 결과와 비트까지 같다.** 근사도, 재결합도, 오차 허용도 없다.

그리고 그 주장을 성립시키는 조건이 **정확히 셋**임을 증명했다.

## ② 필요한 수학

### 결정론은 경합의 문제가 아니다

이것이 이 장의 핵심 통찰이다. 결정론은 **Bernstein 조건**의 문제다:

```
태스크들이 서로의 읽기/쓰기 집합을 건드리지 않으면,
순서를 바꿔도 결과가 같다.
```

09장과 같은 조건이 **다른 결론**을 준다. 경합 없음(안전)과 결정론(재현성)은 다른 성질인데
같은 전제에서 나온다.

### 결합법칙 — 고등학교에서 배운 그것

```
결합적(associative):  (a ⊕ b) ⊕ c = a ⊕ (b ⊕ c)
```

덧셈·곱셈·최대값은 결합적이다. 뺄셈은 아니다:

```
(5 − 3) − 1 = 1
5 − (3 − 1) = 3        ★ 다르다
```

**그리고 부동소수 덧셈도 결합적이 아니다.** 이것이 병렬 축약(reduction)의 함정이다.

## ③ 정리와 그 뜻 — 세 조건

### 정리 D1 — disjoint split 이면 병렬 = 순차

> **Coq 원문**: `Theorem det1_par_eq_seq : forall ts s, Forall local ts -> pw ts -> forall i, par_run ts s i = seq_run ts s i.`

> **평서문**: 태스크들이 **쌍쌍이 독립**(pw)이고 각자 **국소적**(local: 자기 읽기 집합만 보고
> 값을 정한다)이면, 병렬 실행의 **모든 자리 i** 의 값이 순차 실행과 **같다.**

따름정리의 이름이 주장 그대로다: `det1_bit_identical`. **"비트 동일" 은 문자 그대로**다.

증명의 갈림길이 교육적이다. 자리 `i` 를 두고 두 경우로 나눈다:

| 경우 | 논증 |
|---|---|
| `i` 를 첫 태스크가 쓴다 | 나머지 중 누구도 `i` 를 쓰지 않는다(쓰기-쓰기 분리) → 답은 첫 태스크의 것 |
| `i` 를 첫 태스크가 안 쓴다 | 나머지 중 유일한 기록자가 답을 낸다. 그 태스크의 **읽기**가 첫 태스크의 쓰기와 겹치지 않으므로, 원래 상태를 읽든 첫 태스크가 손댄 상태를 읽든 **같은 값** |

두 번째 줄이 `local` 이 왜 필요한지 말해 준다. 태스크가 자기 읽기 집합 밖을 보면 그 논증이
무너진다.

**막는 버그**: "결과가 대체로 맞는" 병렬화. 이 언어에서는 대체로가 없다.

### 정리 D1′ — 겹치면 결정론이 깨진다 (반례)

> **Coq 원문**: `Theorem overlap_is_nondeterministic : ~ indep writes_1 writes_2 /\ seq_run [writes_1; writes_2] zero 0 <> seq_run [writes_2; writes_1] zero 0.`

두 태스크가 같은 자리에 각각 1과 2를 쓴다. 순서에 따라 답이 **1 아니면 2** 다.

```coq
Example race_order_A : seq_run [writes_1; writes_2] zero 0 = 2.
Example race_order_B : seq_run [writes_2; writes_1] zero 0 = 1.
```

★ 09장의 C2 와 같은 방식이다 — **정리 하나에 반례 하나.** 이것이 없으면 D1 은 장식이다
(조건이 과하게 엄격해도 D1 은 참일 수 있으니까).

### 정리 D2 — 스케줄러는 의존 간선만 지키면 된다

> **Coq 원문**: `Theorem det2_schedule_free : forall ts ts', sched_equiv ts ts' -> Forall local ts -> forall s i, seq_run ts s i = seq_run ts' s i.`

> **평서문**: 충돌하지 않는 두 태스크의 **순서를 바꿔도** 결과가 같다. 그러므로 스케줄러는
> **의존(=충돌) 간선만** 지키면 되고 나머지 순서는 자유다.

이것이 "의존 sync" 가 뜻해야 하는 **전부**다. 실용적 값: 스케줄러에게 최대한의 자유를 주면서도
결정론을 잃지 않는다. 자유가 곧 성능이다.

증명은 **인접 교환에 대한 귀납**이다. 인접한 두 개를 바꿀 수 있다면, 그것을 반복해서
"충돌 순서를 지키는 임의의 재배열" 에 도달한다(정렬 알고리즘과 같은 발상).

### 정리 D3 — 축약 트리를 **고정해야** 한다

> **Coq 원문(긍정)**: `Theorem assoc_shape_free : forall op, assoc op -> forall t1 t2, leaves t1 = leaves t2 -> red op t1 = red op t2.`

> **평서문**: 연산이 **결합적이면** 축약 트리의 **모양이 상관없다** — 잎이 같으면 결과가 같다.
> 그러므로 스케줄러가 트리를 골라도 된다.

> **Coq 원문(반례)**: `Theorem nonassoc_shape_matters : ~ assoc sub /\ leaves left_tree = leaves right_tree /\ red sub left_tree <> red sub right_tree.`

> **평서문**: 연산이 결합적이 **아니면** 같은 잎에서 **다른 결과**가 나온다.
> `(5−3)−1 = 1` 대 `5−(3−1) = 3`.

⇒ 결론: **연산이 결합적이 아니면 언어가 트리를 고정해야 한다.** 스케줄러가 코어 수에 따라
트리를 바꾸면 **결과가 스케줄에 의존한다.**

★ 여기서 증명은 IEEE 부동소수를 **공리로 들여오지 않았다**. 대신 뺄셈이라는 **비결합 연산의
대표**로 논증했다. 부동소수 덧셈이 비결합이라는 사실은 잘 알려져 있으니, 그것을 정리에
끌어들이지 않고 *"비결합이면 모양이 문제다"* 를 일반적으로 증명한 것이 더 깨끗하다.

**막는 버그**: 병렬 합산이 코어 수마다 다른 답을 내는 것. 과학 계산에서 재현 불가능의
가장 흔한 원인이다.

## ④ 증명의 전략

세 정리 각각에 **긍정과 반례가 짝**을 이룬다. 표로 보면 설계 조건이 왜 셋인지 보인다:

| 조건 | 있으면 | 없으면 |
|---|---|---|
| DET-1 disjoint split | 병렬 = 순차 (D1) | 순서가 결과를 바꾼다 (D1′) |
| DET-2 의존 sync | 나머지 순서는 자유 (D2) | — (자유를 안 쓰면 손해만) |
| DET-3 고정 축약 트리 | 결합적이면 불필요 (D3 긍정) | 비결합이면 결과가 바뀐다 (D3 반례) |

세 조건이 **독립적으로 필요**하다는 것을 반례가 보인다. 하나를 빼면 어디가 깨지는지가
정리로 적혀 있다. 그러면 나중에 누가 "이 조건은 과하지 않나" 물을 때 **반례를 가리키면 된다.**

## ⑤ 이것이 막는 버그

```
① 두 태스크가 같은 칸에 쓴다        → disjoint split 위반, 결과가 스케줄 의존
② 태스크가 자기 몫 밖을 읽는다      → local 위반, D1 의 두 번째 경우가 무너진다
③ 부동소수 합을 코어 수로 나눠 더함  → 트리가 바뀌면 마지막 비트가 바뀐다
```

③이 실무에서 가장 자주 물린다. "값이 거의 같으니 괜찮다" 로 넘어가는데, 그러면 **회귀
테스트를 비트 비교로 쓸 수 없게 된다.** 재현성을 잃으면 디버깅 도구 하나를 잃는 것이다.

## ⑥ 증명하지 않은 것

정직하게 — **큰 것 하나가 있다.**

1. **level 1 병렬은 아직 구현되지 않았다**(MVP 제외). 그러므로 이 파일은 **구현을 검증하지
   않는다.** 검증한 것은 *"구현이 지켜야 할 조건"* 이다 — DET-1 의 disjoint 가 정확히 무엇이어야
   하는지, DET-3 의 트리를 왜 고정해야 하는지가 정리로 못 박혔다. 구현이 오면 이 조건을
   검사하면 된다.

   ★ 이 순서가 낫다고 본다. 조건을 나중에 발명하면 **구현에 맞춰 느슨해진다.**
2. **상태 모델은 `자리 → 값` 함수다.** 실제 메모리(정렬·별칭·부분 쓰기)를 모델링하지 않았다.
3. **`local` 은 가정이지 검사가 아니다.** "태스크가 자기 읽기 집합만 본다" 를 컴파일러가
   보장해야 하는데, 그 보장의 증명은 여기 없다.
4. **부동소수 자체는 다루지 않았다.** 비결합의 대표로 정수 뺄셈을 썼다. IEEE 754 의 성질
   (반올림·NaN·-0)은 이 파일 밖이다.
