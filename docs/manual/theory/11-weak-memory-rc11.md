# 11. 약한 메모리 — 기본값이면 순서대로 생각해도 된다

> **근거**: `LowentRC11.v` — `sb_sc_impossible`·`sb_relaxed_is_consistent`·`it_is_the_sc_axiom_that_forbids_it`
> ·`sb_relaxed_has_a_race`·`mp_relacq_forbids_stale`·`mp_relaxed_allows_stale`·`mp_sync_is_what_forbids_it`
> · **`LowentRC11Sweep.v`**(litmus 배터리 일곱 + 유계 전수 단조성) · **`LowentOrderExt.v`**(순서 확장)
> (전부 Qed) · **`LowentRC11SC.v`** — `all_sc_is_sc`·`acyclic_sub`·`sw_weaken`·`sc_is_the_strongest`
> (전부 Qed, ∀실행 일반 정리 — ⑥ 참조). 기준 모델 = **RC11**(Lahav et al., PLDI'17).

## ① 5분 요약

CPU 와 컴파일러는 **명령 순서를 바꾼다**. 단일 스레드에서는 티가 안 난다. 여러 스레드가
같은 메모리를 보면 **티가 난다** — 내가 쓴 순서대로 남이 보지 않는다.

이 언어는 원자 연산에 다섯 가지 세기를 노출한다:

```
relaxed  <  acquire / release  <  acq_rel  <  seq_cst
   약함                                        강함(기본값)
```

**기본값이 `seq_cst`** 이고, 약한 것을 쓰려면 **명시**해야 하며 그 코드는 **감사 대상**이다.

이 장은 그 설계 결정이 기대는 **두 명제**를 증명한다:

| | 명제 | 없으면 |
|---|---|---|
| ① | 기본값이면 **SC 로 사고해도 된다** | "기본 seq_cst" 는 위안일 뿐이다 |
| ② | 약한 것은 **진짜로 그것을 깬다** | "명시 + 감사" 가 과장이 된다 |

**둘 다** 증명해야 그 결정이 정당해진다.

## ② 필요한 수학

### 순차 일관성(SC) 이란

*"모든 스레드의 모든 접근을 **한 줄로 세울 수 있고**, 각 스레드 안의 순서가 그 줄에서 지켜진다."*
사람이 자연스럽게 상상하는 그림이 이것이다. 그리고 실제 하드웨어는 이렇게 동작하지 **않는다**.

### 저장 버퍼링(store buffering) — 표준 반례

```
초기: x = 0, y = 0

T1:  x ← 1        T2:  y ← 1
     r1 ← y            r2 ← x

나쁜 결과:  r1 = 0  이고  r2 = 0        ← 둘 다 0
```

왜 나쁜가? 한 줄로 세울 수 없다. `r1 = 0` 이면 T1 의 읽기가 T2 의 쓰기보다 먼저이고,
`r2 = 0` 이면 T2 의 읽기가 T1 의 쓰기보다 먼저다. 그런데 각 스레드 안에서는 쓰기가 읽기보다
먼저다. **모순** — 즉 SC 가 아니다. 그런데 **실제 x86 에서 이 결과가 나온다.**

### 관계 그래프와 순환

RC11 은 실행을 **그래프**로 본다. 이벤트가 정점이고, 간선이 여러 종류다:

| 간선 | 뜻 |
|---|---|
| `hb`(happens-before) | 순서가 보장된다 |
| `rf`(reads-from) | 이 읽기는 저 쓰기의 값을 읽었다 |
| `mo`(modification order) | 한 자리에 대한 쓰기들의 전역 순서 |
| `fr`(from-read) | 이 읽기는 저 쓰기보다 **먼저**다(더 낡은 값을 읽었으므로) |

그리고 판정은 한 문장이다: **"어떤 축에서 순환이 생기면 그 실행은 존재하지 않는다."**

이것이 이 장에 필요한 수학 전부다. **방향 그래프에 사이클이 있나** — 위상 정렬을 배웠다면
아는 개념이다. RC11 이 어려운 것은 개념이 아니라 **간선 종류가 많기** 때문이다.

## ③ 정리와 그 뜻

### 정리 E1 — 기본값(seq_cst)이면 저장 버퍼링이 불가능하다

> **Coq 원문**: `Theorem sb_sc_impossible : consistent (SB SC) rf_00 mo_SB = false.`

> **평서문**: 모든 접근이 `seq_cst` 면 "둘 다 0 을 읽는" 결과는 **일관성 공리를 위반한다** —
> 그런 실행은 없다.

순환을 직접 보자:

```
Wx1 ──hb──▶ Ry0 ──fr──▶ Wy1 ──hb──▶ Rx0 ──fr──▶ Wx1
```

`fr` 간선을 읽는 법: `Ry0` 은 y 의 **초기값**을 읽었는데 `Wy1` 이 그것을 덮어썼다 ⇒ `Ry0` 이
`Wy1` 보다 **먼저**다. 그 네 간선이 **닫힌 고리**를 이루므로 이 실행은 존재할 수 없다. ∎

**이것이 왜 실용적인가**: `seq_cst` 만 쓰는 코드는 **한 줄로 세워 상상해도 된다.**
"기본 seq_cst" 라는 문장이 위안이 아니라 **정리**가 된다.

### 정리 E2 — relaxed 면 그 결과가 **가능하다**

> **Coq 원문**: `Theorem sb_relaxed_is_consistent : consistent (SB Rlx) rf_00 mo_SB = true.`

> **평서문**: `relaxed` 면 그 나쁜 결과가 **모든 공리를 만족한다** — 즉 실제로 일어날 수 있다.

왜 통과하나? SC 공리는 **`seq_cst` 이벤트에 대해서만** 말한다. relaxed 뿐이면 그 공리는
**공허하게 참**이다. **그것이 relaxed 의 값이자 위험이다** — 제약을 걷어 내니 빠르지만, 걷어 낸
것이 바로 안전이다.

E1 과 E2 가 **짝**이다. 하나만으로는 설계를 정당화할 수 없다.

### 정리 E3 — 막는 것은 정확히 **SC 공리**다

> **Coq 원문**:
> ```coq
> Theorem coherence_alone_does_not_forbid_sb :
>   hb_irreflexive … && rf_wellformed … && coherence … = true.
> Theorem it_is_the_sc_axiom_that_forbids_it : sc_acyclic … = false.
> ```

> **평서문**: `seq_cst` 여도 **coherence 축만으로는** 저장 버퍼링이 막히지 않는다.
> 막는 것은 **SC 축**이다.

이 정리에는 **실패담**이 붙어 있다. 처음 쓴 모델은 저장 버퍼링을 `seq_cst` 에서도
**통과시켰다**(공리가 모자랐다). 즉 모델이 틀렸다. 그것을 **기계가 가르쳐 줬고**, 공리를
보태서 고쳤다. 그리고 이 두 정리는 그 교훈을 **고정**한다 — 어느 축이 일하는지 명시적으로
적어 두면, 나중에 누가 공리를 지웠을 때 이 정리가 깨진다.

> **모델이 틀렸음을 기계가 가르쳐 준다.** 증명 도구의 진짜 값은 정리를 얻는 것보다 여기에 있다.

### 정리 E4 — 메시지 전달: acquire/release 가 실제로 작동한다

E1~E3 은 "약한 것이 위험하다" 였다. 그러면 약한 것은 왜 있나? **정확히 이 모양을 위해서**다.

```
T1:  data ← 1      (평범한 쓰기)      T2:  flag 를 읽는다  (acquire)
     flag ← 1      (release)               data 를 읽는다  (평범)

나쁜 결과 = flag=1 을 읽고도 **data=0** 을 읽는다      ← 낡은 값
```

> **Coq 원문**:
> ```coq
> Theorem mp_relacq_forbids_stale  : consistent (MP Rel Acq) rf_MP mo_MP = false.   (* 불가능 *)
> Theorem mp_relaxed_allows_stale  : consistent (MP Rlx Rlx) rf_MP mo_MP = true.    (* 가능 *)
> Theorem mp_sync_is_what_forbids_it : sw (MP Rel Acq) … = true /\ sw (MP Rlx Rlx) … = false.
> ```

> **평서문**:
> ① **release/acquire 면** 낡은 값을 보는 것이 **불가능**하다.
> ② **relaxed 면 가능**하다.
> ③ 차이를 만드는 것은 **동기화 간선(sw)** 이다 — release 쓰기와 acquire 읽기 **사이에** 선다.

①의 논증: `sw`(3→4)가 `hb`(2→5)를 만든다. 그런데 data-읽기(5)가 초기값을 읽었고 data-쓰기(2)가
그보다 mo-나중이므로 `fr`(5→2)이 선다. `hb`(2→5)와 `fr`(5→2)가 **같은 자리에서 순환**을 이루므로
coherence 축이 막는다.

E4 는 E1 과 **짝**이다. E1 은 "기본값이 안전하다", E4 는 "명시하면 동기화된다" — 이제
설계 결정의 **양쪽 방향**이 기계 위에 있다.

### 정리 E5 — 그 나쁜 실행에는 **경합이 있다**

> **Coq 원문**: `Theorem sb_relaxed_has_a_race : race_free (SB Rlx) rf_00 = false.`

> **평서문**: 저장 버퍼링의 (0,0) 결과가 나오는 실행은 **경합을 담고 있다.**

이 한 줄이 9·10·11장을 묶는다:

```
level 1·2 는 그런 실행을 **만들 수가 없다**  (09장, Qed)
      ↓
그러므로 level 1·2 코드는 이 장을 읽지 않아도 된다.
      ↓
약한 메모리는 level 3 만의 문제다 — **가둠(containment)이 성립한다.**
```

## ④ 증명의 전략 — 계산으로 증명하기

이 파일의 증명은 대부분 이렇게 생겼다:

```coq
Proof. vm_compute. reflexivity. Qed.
```

`consistent` 를 **판정 함수**(불리언을 내는 프로그램)로 정의했으므로, 특정 실행에 대해
그 함수를 **계산해 버리면** 증명이 끝난다. 손으로 논증할 것이 없다.

이 방식의 장점과 대가:

| | |
|---|---|
| 장점 | 증명이 짧고, 모델을 고치면 **자동으로 재검증**된다 |
| 대가 | **특정 실행**에 대한 결과다 — 임의 프로그램에 대한 일반 정리가 아니다 |

즉 이것은 "**이 반례가 막힌다/막히지 않는다**" 를 기계로 확정한 것이다. 그리고 그것으로
설계 결정을 정당화하기에는 **충분하다** — 결정이 걸려 있는 것이 바로 그 표준 반례들이니까.

## ⑤ 이것이 막는 버그

```lowent
rem ① relaxed 로 플래그 동기화 — 낡은 데이터를 본다 (E4-②)
atomic_store_relaxed flag 1 .     rem ✘ data 쓰기가 따라오지 않을 수 있다

rem ② 올바른 모양 — release/acquire (E4-①)
atomic_store_release flag 1 .
… atomic_load_acquire flag …      rem ✔ 앞선 data 쓰기가 반드시 보인다

rem ③ 기본값 — 아무것도 명시하지 않으면 seq_cst (E1)
rem   느리지만 **순서대로 생각해도 된다**. 이것이 옳은 기본값이다.
```

기본값이 왜 `seq_cst` 여야 하는지가 이제 명확하다. 기본값을 relaxed 로 두면 **아무 표시 없는
코드가 위험**해진다. 위험은 **명시적으로 요청해야** 얻는 것이어야 한다.

## ⑥ 증명하지 않은 것

정직하게 — 이 장의 경계가 문서 전체에서 가장 중요하다.

1. **RC11 전체의 SC 정리 — 절반은 증명했다.**

   "저장 버퍼링이라는 특정 반례가 막힌다" 에서 그치지 않고, 모든 실행에 대한 정리를 순수 Coq 으로
   세웠다(무거운 동시성 논리 없이):

   > **정리**(`LowentRC11SC.v`의 `all_sc_is_sc`, Qed):
   > `all_sc E = true -> consistent E rf mo = true -> sc_com_acyclic E rf mo = true`
   >
   > **평서문**: 모든 접근이 `seq_cst` 이고 그 실행이 RC11 일관적이면, `po ∪ rf ∪ mo ∪ fr` 에
   > **순환이 없다** — **∀ 실행 · ∀ rf · ∀ mo.**

   공리적 메모리 모델에서 *"이 실행은 SC 다"* 를 그렇게 정의하는 것이 표준이다
   (SC ⟺ acyclic(po ∪ com)). 즉 이 장의 주장이 **예제 하나에서 모든 실행으로** 올라갔다.

   증명의 엔진은 한 줄이다: **부분관계는 비순환성을 물려받는다.** 모든 접근이 `seq_cst` 면
   `po ∪ eco` 의 모든 간선이 psc 간선이므로(po ⊆ hb), SC 공리가 주는 psc 비순환성이
   그 부분관계로 내려온다.

   **단조성도 정리다**(`LowentRC11Mono.v`):

   > `consistent_monotone`(Qed): 같은 실행에서 **mode 만 약하게 한 것**이 일관적이다 —
   > **∀ 실행 · ∀ rf · ∀ mo · ∀ 배정.**

   평서문: **약하게 적으면 거동이 늘어난다(줄지 않는다).** 뒤집으면 실무에서 쓰는 문장이 된다:
   **ordering 을 세게 적는 것은 언제나 안전한 방향이다.** 기본값을 `seq_cst` 로 둔 근거가 바로
   이 문장이고, 그것은 **믿음이 아니라 정리**다. 유계 전수 계산으로는 3 이벤트 골격까지만 닫혔지만,
   증명은 이벤트 수와 무관하게 닫힌다.

   그리고 그 증명이 **모델의 결함을 하나 찾았다.** 옛 세기 순서는 `AcqRel` 을 `SC` **위에**
   놓았다 — sw(동기화) 간선만 재고 `is_sc` 를 안 봤기 때문이다. 그런데 SB 는 AcqRel 에서
   **일관**이고 SC 에서 **불일관**이다(`old_order_is_not_a_strength_order` 가 그것을 계산한다).
   즉 그 순서로는 단조성이 **거짓**이었다. 유계 전수가 못 본 이유도 분명하다: 그 골격들이
   **psc 축을 건드리지 않는다.** ⇒ 순서를 고쳐(`stronger_sc`) SC 를 유일한 꼭대기로 만들었다.

   **남은 한 걸음도 절반을 갚았다**(`LowentOrderExt.v`): *"비순환 ⟹ 전순서 존재"* 를
   추상적으로 논증하는 대신 **위상 정렬을 함수로 짓고** 그 결과가 진짜 선형 확장임을 증명했다.

   > `topo_linearises`(Qed): `topo_of R nodes = Some L` 이면 **R 의 모든 간선이 L 에서 앞→뒤다.**
   > `sc_witness_orders_everything`(Qed): 그러므로 `po ∪ rf ∪ mo ∪ fr` 의 모든 간선이 그 줄에서
   > 앞에서 뒤로 간다 — **모든 접근을 한 줄로 늘어놓았고, 그 줄이 프로그램 순서와 통신 순서를
   > 전부 지킨다.**

   실제로 순서가 나온다: seq_cst 로 둔 좋은 SB 실행에서 `[0; 1; 2; 4; 3; 5]` 가 나오고
   그것이 선형 확장임이 계산으로 확인된다(`the_good_sb_execution_has_an_order`).

   **아직 없는 것**: *"비순환이면 topo 가 **반드시** 성공한다"*(즉 `Some` 임). 그것은
   **비둘기집 논증** + *"길이 k 의 걸음은 `closure m`(m ≥ log₂k) 안에 있다"* 라는 보조정리를
   요구한다(`step` 이 한 번에 경로 길이를 두 배로 늘리므로 귀납은 자연스럽다).
   ⇒ 지금 상태의 실용적 값은 이것이다: **순서를 실제로 얻고, 그것이 옳음을 안다.**
   실패하면 `None` 으로 **알 수 있다** — 조용히 틀린 순서를 내는 일은 없다.

   그리고 세 문제를 가르면 이렇게 된다:

   | | 무엇 | 실제로 필요한 것 |
   |---|---|---|
   | (a) **모델 내부 메타정리** | 모든 접근이 seq_cst ⟹ SC(**갚음**) · 단조성(간선 수준 **갚음**) · DRF-SC | **순수 Coq**. Iris 불필요 |
   | (b) **프로그램 논리** | 특정 lock-free 알고리즘을 relaxed 로 검증 | **진짜 iGPS/Cosmo** |
   | (c) **컴파일 매핑** | RC11 ordering → 기계어 | 별개 문헌 (아래 4번) |

   (a)는 **관계 그래프에 대한 주장**이므로 분리논리가 필요 없다 — 위에서 실제로 그렇게 갚았다.
   무거운 도구가 필요하다고 여겼던 **DRF-SC** 도 `LowentDRF.v` 가 **순수 Coq 으로 닫았다**(09장).

   단조성도 간선 수준까지 갚았다(`sw_weaken`): **ordering 을 약하게 하면 동기화 간선이
   줄어든다**(없던 것이 생기지 않는다). 그리고 `sc_is_the_strongest`·`rlx_is_the_weakest` 로
   mode 의 세기 순서가 정리가 됐다 — **`seq_cst` 가 기본값으로 옳다**는 말의 형식적 내용이
   *"모든 mode 보다 세다"* 다. 그것을 "consistent 가 보존된다" 로 잇는 것은 남았지만
   **방향은 확인됐다**: 모든 공리에서 hb 간선이 늘면 통과가 **더 어려워진다**.
2. **모델은 손으로 옮긴 RC11 이다.** 논문의 정의와 일치하는지는 **사람이 읽어서**
   확인했다(그리고 한 번 틀렸다 — E3 의 실패담). 논문과의 대응은 기계 검증되지 않았다.
3. **문헌의 이름 있는 시험 일곱을 먹였다**(`LowentRC11Sweep.v`). 손으로 고른 실행만 쓰면 모델의 공리가
   모자란 것을 못 잡는다(E3 의 실패담) — 그래서 이 시험들을 쓴다:

   | 시험 | seq_cst | relaxed |
   |---|---|---|
   | SB · LB · MP · 2+2W · IRIW | **금지**(`sc_forbids_the_battery`) | **허용**(`relaxed_allows_the_weak_ones`) |
   | CoRR · CoWR (per-location coherence) | 금지 | **금지** ← 성격이 다르다 |

   마지막 줄이 배운 것이다: **"relaxed = 아무 보장 없음" 이 아니다.** SB 를 막는 것은 SC 축이고
   CoRR/CoWR 을 막는 것은 **coherence 축**인데, 후자는 ordering 과 무관하게 **늘 있다.**
   그리고 `acqrel_also_synchronises` 로 다섯 ordering 낱말이 모두 기계 위에 올랐다.

   여전히 표본이다: **fence 를 쓰는 시험이 하나도 없다**(이 모델에 fence 이벤트가 없다).
   herd7 급 모음은 수백 개다. 그리고 rf/mo 는 각 골격당 **하나씩**(그 나쁜 결과)이다 —
   모든 rf/mo 후보 열거가 진짜 "전수" 이고, 지금은 아니다.
4. **컴파일러가 이 모델을 지키는지는 별개다.** 정리는 모델에 대한 것이고, 실제 코드 생성이
   그 ordering 을 올바른 기계어로 낮추는지는 검증되지 않았다.
   다만 이 언어는 **C11 atomic 으로 방출**하므로 의무가 "우리 ordering → C11 ordering" 으로
   줄어든다. 그 매핑이 **1:1 이고 우리가 atomic 을 재배치하지 않는다**면 나머지는 C 컴파일러의
   몫이다(TCB 에 이미 들어 있다 — 16장 ④). 그 두 조건은 **시험으로 확인할 수 있다.**
