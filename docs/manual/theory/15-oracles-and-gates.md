# 15. 컴파일러를 어떻게 검증하나

증명은 **모델**에 대한 것이다(01장). 실제 컴파일러가 그 모델을 따라가는지는 따로 확인해야 한다.
이 장은 그 확인 방법을 한 쪽으로 정리한다. 원리는 하나다:

> **같은 것을 두 가지 방법으로 만들고, 답이 다르면 결함으로 본다.**

두 구현이 다른 답을 내면 적어도 하나는 틀렸다. 반대로 같은 답을 낸다고 둘 다 맞다는 뜻은 아니다 —
그래서 이런 검사는 결함이 **있음**을 보이지만 **없음**을 보이지는 못한다. 없음은 증명(`docs/proofs/`)의 몫이다.

## 다섯 가지 맞대기

| 방법 | 무엇과 무엇을 맞대나 | 무엇을 잡나 |
|---|---|---|
| **두 백엔드 대조** | VM 실행 ↔ C 로 낸 네이티브 실행 | 두 백엔드가 다른 답을 내는 곳 |
| **계약 대조** | 적어 둔 계약 ↔ 실제 실행 결과 | 계약이 사실과 다른 곳 |
| **분석 자기 점검** | 컴파일러가 "안전하다"고 믿은 인덱스 ↔ 실제 인덱스 | 분석이 틀린 곳(`E-VM-ANALYSIS`) |
| **증명서 검산** | 검사를 지운 근거 ↔ 독립 검산기의 산술 | 규칙을 잘못 적용한 곳 |
| **한 줄 바꾸기** | 프로그램 ↔ 사실 하나를 지운 프로그램 | 정답을 몰라도 관계가 깨진 곳 |

- **두 백엔드 대조**는 op 마다 경계값으로 인자를 만들어 VM 과 네이티브를 돌리고 출력을 바이트 단위로 비교한다.
  둘 다 같은 진단으로 거절하는 것도 "같은 답"으로 친다.
- **계약 대조**는 기대 출력을 따로 적지 않는다. `requires`·`ensures`·`errors` 가 곧 판정 기준이다.
- **증명서 검산**은 컴파일러가 범위 검사를 지울 때 남긴 산술 근거(Farkas 증명서)를 컴파일러와 따로 짠
  검산기가 다시 계산한다. 검산기 가운데 하나는 규칙의 건전성을 증명한 Coq 코드에서 뽑아낸 것이다(`docs/proofs/coq/LowentCert.v` · `LowentCertExtract.v`).
- **한 줄 바꾸기**는 사실 하나를 지운 프로그램이 원래보다 **더 많이** 증명되면 결함으로 본다.

## 공개 저장소에서 직접 돌려 볼 수 있는 것

```sh
cd impl
make check
```

- 단위 시험, 표준 라이브러리 전체 `--check`, 여러 op 의 VM·네이티브 대조, 거절되어야 하는 프로그램의
  진단 코드를 한 번에 본다. 무엇을 보는지는 `impl/tests/smoke.sh` 머리말에 적혀 있다.
- 명세와 매뉴얼의 예제는 "컴파일된다"고 적힌 것은 컴파일되고, "거절된다"고 적힌 것은 그 진단으로
  거절되는지 개발 저장소의 검사가 매번 확인한다.
