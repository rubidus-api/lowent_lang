# 16. 증명하지 않은 것 — 이 문서가 정직하기 위한 조건

> **근거**: [`docs/proofs/LEDGER.md`](../../proofs/LEDGER.md)(증명 원장) · [`docs/proofs/coq/`](../../proofs/coq/).
> 이 장이 **마지막**인 것은 편집상의 우연이 아니다 — 앞의 열다섯 장이 무엇을 주장했는지
> 알고 나서야 그 경계가 뜻을 갖는다.

## ① 왜 이 장이 있나

증명을 자랑하는 문서는 대개 두 가지 중 하나를 한다: **경계를 안 적거나**, 맨 앞에 한 줄로
면피하고 잊는다. 둘 다 읽는 사람을 잘못된 확신으로 데려간다.

> **증명의 값은 그것이 무엇을 덮지 않는지 아는 데서 나온다.**

## ② 세 등급 — 낱말을 섞지 않는다

| 낱말 | 뜻 | 얼마나 센가 |
|---|---|---|
| **증명됨** | Coq 이 모든 경우를 확인했다 | 반례가 **존재할 수 없다**(모델 안에서) |
| **전수 검사됨** | 정해진 크기의 **모든** 경우를 실제로 돌렸다 | 그 크기 안에서 확실. **밖은 모른다** |
| **스케치** | 사람이 논증했고 기계가 확인하지 않았다 | 사람만큼 믿을 만하다 |

"이 언어는 증명됐다" 가 사실은 "짧은 경우들을 돌려 봤다" 인 경우가 흔하다. 이 문서는 셋을 섞지 않는다.

## ③ 무엇이 증명됐나 — 실측 장부

```
기계 검증 파일       31        docs/proofs/coq/*.v (검사기 추출 파일 1 포함)
Theorem             179
Corollary            15
Lemma               250
Example              33
증명 스크립트 줄 수 10,350
검증 도구             2        Rocq 9.2 — 전부 · Coq 8.20.1 — 약한 메모리(iRC11·gpfsl) 둘을 뺀 나머지
Admitted · Axiom      0        "참이라고 치고 넘어간다" 가 하나도 없다
```

Coq 에서 `Admitted` 는 *"이건 참이라고 치고 넘어간다"* 이고, `Axiom` 은 *"이건 가정한다"* 다. 그런 자리가
하나라도 있으면 그 파일의 모든 정리가 그 가정에 기댄다. **둘 다 0 이다.**

| 주제 | 등급 | 장 |
|---|---|---|
| 수치 코어(안전 확대·나눗셈 트랩·rem/mod) | **증명됨** | 03 |
| 타입 규칙(수치 식 · 참조·슬라이스·호출 · enum · 제네릭 단형화) | **증명됨**(부분 — effect-row 는 밖) | 03 |
| 소유·차용(직선·place·op 경계) | **증명됨** | 06 |
| 루프(모든 반복 횟수) · 중첩 루프 · 분기 합류 | **증명됨** | 07 |
| 효과 체계의 건전성 · 효과 기반 최적화의 적법성 | **증명됨** | 08 |
| 데이터 경합 자유(level 1·2) | **증명됨** | 09 |
| 결정론 병렬(DET-1·2·3) | **증명됨** | 10 |
| RC11: 모든 접근이 seq_cst ⟹ SC(∀실행) · 단조성 · 순서 확장 | **증명됨** | 11 |
| RC11: 문헌의 litmus 시험 일곱 | **전수 검사됨** — 그 시험들 안에서 | 11 |
| CAS 스핀락 상호배제 · rwlock · 교착 자유 · 굶주림 없음 | **증명됨**(락은 Iris) | 12 |
| 약한 메모리 메시지 전달 · SPSC 링버퍼 | **증명됨**(gpfsl 의 증명을 **빌렸다**) | 12 |
| 점-닫힘 문법 | **증명됨** | 13 |
| 내용 주소화의 성질(H1·H2·H3) · 인코딩의 단사성 | **증명됨** — BLAKE3 충돌 저항성은 가정 | 14 |
| 경계 검사 제거의 근거(구간 산술·narrow·div) | **증명됨** | 05·15 |
| 구현↔모델 대응(차용) | **전수 검사됨** — 10,490,024 시퀀스 / 90,376 형태 | 06·07 |

## ④ 신뢰 기반(TCB) — 증명이 기대는 것들

| 믿는 것 | 왜 믿나 | 틀리면 |
|---|---|---|
| **Coq/Rocq 의 커널** | 작은 핵 · 두 판(8.20·9.2)이 같은 답을 낸다 | 모든 정리가 무의미 |
| **Iris** | 12장에만 필요 | 락 정리만 무너진다 |
| **iRC11 / gpfsl** · iris `rw_spin_lock` | 약한 메모리·rwlock 읽기 쪽 · **증명을 빌렸다** | 그 정리들만 무너진다 |
| **C 컴파일러**(gcc/clang) | 대안이 없다 | 네이티브 코드가 IR 과 달라진다 |
| **BLAKE3 의 충돌 저항** | 14장의 전제 | 캐시가 다른 내용을 같다고 본다 |
| **운영체제·하드웨어** | 대안이 없다 | 전부 |
| **`proven_c_lib`**(기반 라이브러리) | 자체 테스트 | 자료구조가 조용히 틀린다 |
| **모델이 언어를 옳게 담았다** | 사람이 읽어서 확인 | 아래 ⑤ |

## ⑤ 가장 큰 간극 — 모델과 구현 사이

```
정리는 모델에 대한 것이다.
모델은 사람이 쓴 것이다.
컴파일러는 다른 언어로 쓴 다른 코드다.
그 둘이 같다는 것은 증명되지 않았다.
```

이음매를 잇는 것들(자세한 방법은 15장):

| 이음매 | 무엇을 하나 | 성격 |
|---|---|---|
| 유계 전수 모델 검사 | 작은 크기의 모든 경우에서 모델 판정과 구현 판정이 같은지 | **경험적** |
| 실제 프로그램에서 뽑은 이벤트 | 진짜 프로그램의 차용 이벤트를 같은 모델에 먹인다 | **경험적** · 실제 프로그램 |
| 두 백엔드 대조(VM ≡ 네이티브) | 두 실행이 같은 답을 내는지 | **경험적** |
| 분석 자기 점검(`E-VM-ANALYSIS`) | 컴파일러의 "지워도 된다" 를 실행으로 반박 | **경험적** |
| 증명서 검산 | 지운 검사의 근거를 독립 검산기가 산술로 다시 따진다(검산기 하나는 Coq 증명에서 추출) | **정적** |
| 회귀 시험 | 출력이 바뀌면 보인다 | **회귀만** |

앞의 넷은 경험적이다 — "지금 출력이 옳다" 가 아니라 "이 입력들에서 어긋나지 않았다" 를 말한다.
증명서 검산은 성격이 다르다: 그 자리를 때리는 입력이 없어도 말한다. 다만 그것도 **사실을 믿고 추론만** 검사한다.

두 층은 서로 다른 것을 잡는다. 증명이 못 잡은 결함을 대조가 잡았고, 대조가 못 잡은 결함을 증명이 잡았다.
겹쳐 쓰는 이유가 이것이다.

**가장 약한 이음매는 앞단(어휘·파서)이다.** 두 백엔드 대조는 VM 과 네이티브를 비교하지만 둘은 **같은 앞단**을
지난다 — 앞단이 틀리면 둘 다 똑같이 틀린다. 파서가 13장의 모델이라는 것을 직접 대조하려던 시도는 모델이
실제 문법보다 작아서(선언 머리의 절 가르기 등) 과장 없이 결론 낼 만큼의 짝을 얻지 못했다. 이 자리를 닫으려면
앞단을 독립적으로 한 벌 더 구현해 대조해야 하고, 그 비용(두 벌 유지)은 아직 치르지 않았다.

## ⑥ 남은 것 — 주제별

### 언어 코어

| 무엇 | 상태 |
|---|---|
| 효과 체계 | 증명됨. `task_group` 이 `concurrent` 를 흡수하는 규칙과 효과 폐포는 **모델 밖** |
| 효과 기반 최적화 | 증명됨(재정렬·CSE·memoize·죽은 코드 제거). **호출 경계와 트랩 시점은 밖** |
| 루프의 종료성 | **다루지 않는다**(무한 루프는 정당한 프로그램) |
| 타입 체계 전체의 건전성 | **부분** — effect-row 는 미증명 |

### 동시성

| 무엇 | 상태 |
|---|---|
| RC11 일반 약한 ordering | **부분** — 모델 안의 메타정리는 증명됨. 특정 lock-free 알고리즘을 relaxed 로 검증하는 **프로그램 논리**는 SPSC 하나만(빌린 증명) |
| 교착 자유 | 증명됨 — 단 **잠금 오름차순 규율**을 쓰는 사람이 지켜야 한다(도구가 강제하지 않는다) |
| 굶주림 없음 | 증명됨 — T0 라운드로빈 · **양보를 가정**한다 · 우선순위·차단은 밖 |
| level 1 병렬의 구현 | 구현됨 · 정리는 구현을 검증하지 않는다 |
| lock-free 자료구조 | SPSC 링버퍼 하나. MPSC·MPMC·seqlock 은 **빌릴 증명이 없어 넣지 않았다** |
| 컴파일 매핑(RC11 ordering → 기계어) | C11 atomic 으로 1:1 방출하므로 나머지는 C 컴파일러(TCB)의 몫 — 그 매핑 자체는 시험으로 확인 |

### 도구와 빌드

| 무엇 | 상태 |
|---|---|
| 정규화의 완전성 | **부분** — 효과는 집합으로 정규화(증명됨). 계약 절은 적힌 차례에 민감하고, 그것이 **안전한 방향**임을 증명했다 |
| SCC 그룹 해시의 다구현 호환 | **미확정** — 명세 수준의 약속 |
| 파서 ≡ 13장 모델 | **미증명** — ⑤ |

### 기능 범위

| 무엇 | 상태 |
|---|---|
| 부동소수의 성질(IEEE 754 반올림·NaN·-0) | **다루지 않았다** |
| 구간 분석의 부동소수 지원 | **없다** |
| `page_fault`·`blocking` 등 효과 원자 | 어휘만 있고 원시 연산이 없다 |
| effect-row 다형성 | **없다** |

## ⑦ "전면 정적 안전" 으로 팔지 않는다

```
정적으로 막는 것   차용 · 지역 · 저장 참조 · 병렬 겹침 · 정수 확대
런타임이 막는 것   경계 검사(증명 안 된 자리) · 오버플로 트랩 · 계약 검사
                   그래프 핸들의 dangling(세대 핸들 — 동적)
```

**하이브리드**다. 그리고 그것을 정적이라고 부르지 않는다.

비교를 정직하게 적으면: Rust 는 RustBelt 로 증명이 있고, Zig 는 안전을 **주장하지 않는다**
(그것도 정직한 태도다). Lowent 는 "증명 있음 — **주로 순차 단편에 대해**" 다. 그 조건절을 떼면 거짓말이 된다.

## ⑧ 그래서 무엇을 믿어야 하나

```
✔ 정수가 조용히 값을 바꾸는 일은 없다              (03장 · 증명됨)
✔ 통과한 코드에 차용 위반은 없다                    (06·07장 · 증명됨, 순차)
✔ 효과 선언이 실제로 일어나는 효과를 덮는다          (08장 · 증명됨, 모델 안)
✔ 안전 코드에 데이터 경합은 없다                    (09장 · 증명됨)
✔ 병렬 결과는 순차와 비트까지 같다                  (10장 · 증명됨)
✔ 기본 ordering 이면 순서대로 사고해도 된다         (11장 · 증명됨, ∀실행)
✔ 경계 검사를 지운 자리는 범위 안임이 논증된 자리   (05장 · 증명됨 + 검산)

△ 컴파일러가 이 모델을 정확히 따라간다              (⑤ · 경험적)
△ 약한 ordering 을 명시한 코드                       (11·12장 · SPSC 하나만 증명 — 나머지는 감사 대상)
✘ 부동소수의 세부                                    (다루지 않았다)
```

마지막 줄들이 있는 문서를 믿어도 된다. 없는 문서는 다시 봐야 한다.
