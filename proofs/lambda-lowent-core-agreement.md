## 1. 대상 단편 (구현된 S5 코어의 추상화)

op 본문 = **문장열** `st_1; …; st_n` (reader 재조합 후). 차용 관련 이벤트만 남긴다:

```
이벤트  ev ::= create(τ, x, μ)      τ = 차용 태그(유일), x = 지역, μ ∈ {shr, exc}
             | use(τ, rw)           차용 τ를 통한 접근, rw ∈ {rd, wr}
             | own(x, rw)           소유자(이름 x 직접) 접근
             | loop [ ev* ]         while/for 본문 (중첩 가능; 유한 전개 의미)
```

- `create`는 var-바인딩(`var a be … mut_ref x .`)과 일시 차용(호출 인자)을 통칭한다.
  일시 차용은 같은 이벤트 위치에서 create 직후 use로 모델링.
- `deref r` = use(τ_r, rd); `set r v`(write-through) = use(τ_r, wr);
  `set x v` = own(x, wr); 식에서의 `x` 언급 = own(x, rd).
- view/try_view/view_array 는 create(τ, s, shr)로 환원된다(구현과 동일).

**tick**: 이벤트에 텍스트 순서 번호 t(ev)를 부여한다(구현의 statement tick).

## 2. 정적 판정 (interval-EXCL v2 = low_region.c)

차용 τ의 **정적 생존 구간** `I(τ) = [c(τ), l(τ)]`:
c(τ) = t(create), l(τ) = max{ t(use(τ,·)) } (사용이 없으면 c(τ)).

루프 span: `ls(ev)` = ev를 감싸는 최내곽 loop의 시작 tick (없으면 0).

정적 거부 규칙 (구현의 excl2_conflicts와 1:1):

```
경로 문맥  path(ev) = ev를 감싸는 (if-id, arm) 사슬.
compat(a,b) ⟺ 공통 if-id에서 arm이 어긋나지 않음
             (어긋나면 두 이벤트는 *한 실행에 함께 나타날 수 없다*)

(S1) 차용×차용   τ≠τ'(τ 먼저) 이 같은 x를 차용, μ(τ)=exc ∨ μ(τ')=exc,
                 ∃ use(τ) at t_u ≥ c(τ')  ∧  compat(path(use), path(c(τ')))
                                                                    → E-EXCL
                 [t_u ≥ c(τ') 는 I(τ) ∩ I(τ') ≠ ∅ 와 동치(생성 순서 ∵ c(τ)<c(τ'))]
(S2) 소유자×차용 own(x,rw) at t, τ가 x 차용, (μ(τ)=exc ∨ rw=wr), c(τ) < t,
                 ∃ use(τ) at t_u ≥ t  ∧  compat(path(use), path(own))
                                                                    → E-EXCL
(S2L) 루프 span  own이 loop 안(ls>0)이고 c(τ) < ls ≤ l(τ)
                 (차용이 루프를 가로지름) — **경로 문맥 무시**        → E-EXCL
      또한 S1의 use가 루프 안이고 c(τ') < ls 이면 compat 요구를 면제한다.
```

**경로 민감성의 건전성 논거(D4 수정, 2026-07-10).** ⚡는 *한 실행 트레이스* 안의
두 이벤트로만 발생한다. 서로 다른 if-arm의 이벤트는 한 트레이스에 공존할 수
없으므로 그 짝을 건너뛰어도 거짓음성이 생기지 않는다. 유일한 예외가 **루프 반복
간 공존**(반복 k는 A-arm, 반복 k+1은 B-arm)인데, 이는 차용이 루프를 가로질러
살아 있을 때만 문제가 되고 그 경우는 S2L(및 S1의 루프 면제)이 경로-무시로
잡는다. 루프 *안에서* 생성된 차용은 반복마다 신선한 태그라 반복 간 공존이
무의미하다. — §8의 전수 모델 체크가 이 논거를 유계 내에서 기계 확인한다.

프로그램이 **static-green** ⟺ 어떤 규칙도 발화하지 않음.

## 3. 동적 의미 (borrow-stack = low_ir.c VM)

지역 x마다 스택 `B(x)` (아래→위 = 오래된→새 차용):

```
(D1) create(τ,x,μ):  B(x) := B(x) ++ [τ^μ]
(D2) use(τ,rd):      τ ∉ B(x) → ⚡E-VM-EXCL
                     else B(x)에서 τ 위의 exc 항목 제거
(D3) use(τ,wr):      τ ∉ B(x) → ⚡  (μ(τ)=shr 은 별도 ⚡READONLY)
                     else τ 위의 모든 항목 제거
(D4) own(x,rd):      B(x)의 exc 항목 전부 제거          (무효화, 오류 아님)
(D5) own(x,wr):      B(x) := []                          (전부 무효화)
```

실행이 **dyn-clean** ⟺ ⚡가 발생하지 않음.

## 4. 정리 A (직선 단편 합치)

**정리 A.** loop가 없는 이벤트 열에서, static-green ⇒ dyn-clean.

*증명.* 다음 불변식을 이벤트 순서 귀납으로 유지한다:

> **INV:** 각 τ에 대해 τ ∈ B(x) ⟺ c(τ) 이후 지금까지
> (i) own(x,wr)이 없었고, (ii) μ(τ)=exc면 own(x,rd)도 없었고,
> (iii) τ보다 늦게 생성된 τ'의 use(τ',wr)가 없었다.

⚡는 D2/D3의 τ ∉ B(x)에서만 난다. use(τ,·) at t가 ⚡라 하자. t ≤ l(τ)이므로
INV의 부정에 의해 c(τ)와 t 사이에 (i)(ii)(iii) 중 하나가 존재한다.

- **(i) own(x,wr) at t', c(τ) < t' < t ≤ l(τ):** S2가 (rw=wr) 발화 — static-green 모순.
- **(ii) μ(τ)=exc, own(x,rd) at t':** 같은 구간 조건으로 S2 발화(μ=exc) — 모순.
- **(iii) use(τ',wr) at t', c(τ') > c(τ):** τ'는 x의 차용이고 μ(τ')=exc(쓰기 가능).
  t' ≤ l(τ'), 그리고 c(τ') < t' < t ≤ l(τ)이므로 I(τ) ∩ I(τ') ⊇ {t'} ≠ ∅.
  exc 포함이므로 S1 발화 — 모순.

세 경우 모두 모순이므로 ⚡ 불가. INV 자체의 보존은 D1~D5 각 규칙이 INV의
우변 조건과 정확히 같은 시점에 스택을 갱신함으로 직접 확인된다
(D1: 새 τ 삽입 시 (i)~(iii) 공허참; D2/D3/D4/D5: 제거가 조건 발생과 동시). ∎

**따름정리 A'.** READONLY(⚡ from shr 쓰기)는 정적 E-TYPE-REF와 합치한다 —
shr 차용을 통한 wr은 타입 판정이 거부하므로 static-green 프로그램에 없다.

## 5. 보조정리 B (루프 span — 스케치)

**보조정리 B.** loop [ evs ]의 유한 전개 evs^k (k ≥ 1 임의)에 대해:
루프 밖에서 생성되어 루프 안에서 사용되는 τ(즉 c(τ) < ls ≤ l(τ))와
루프 안의 own(x,·)이 공존하면, 어떤 k ≥ 2 전개에서 정리 A의 (i)/(ii) 상황이
회전(wrap-around)으로 발생할 수 있다. S2L은 정확히 이 짝을 거부하므로
static-green ⇒ 모든 k 전개가 dyn-clean.

*스케치.* 전개 evs^k에서 i번째 반복의 own이 (i+1)번째 반복의 use(τ,·)에
선행한다. τ의 정적 구간은 전개 전 텍스트 순서로는 own 뒤에서 끝날 수 있어
S2(정확 구간)로는 놓친다 — S2L이 span 포함(c<ls≤l)만으로 거부해 보수 근사.
루프 안에서 생성된 차용(c ≥ ls)은 반복마다 신선한 τ라 회전 영향이 없고
정확 규칙(S1/S2)이 반복 내부 순서로 적용된다(구현의 fresh-tag와 일치). ◻

주: S2L은 **보수적**이다(전개상 실제로는 무해한 순서도 거부 가능) — 건전성
방향(거짓음성 없음)은 유지하고 정밀도만 양보한다. 관측된 오탐 부류는 §6-D4.

## 6. 발견된 설계 결함 기록 (V2 산출물)

- **D1 (수정됨) reader-split 바인딩 누락.** 순수 reader가
  `var a be mut_ref u64 mut_ref x .`를 형제 form으로 쪼개 정적 EXCL이 차용
  등록을 통째로 놓쳤다. *동적 검증기(borrow-stack)가 가동 당일 발견* —
  two_mut가 --check 통과 후 ⚡. 수정: 블록 레벨 재조합. (커밋 3b3447e)
- **D2 (수정됨) 렉시컬 EXCL의 소유자 접근 미추적.** own(x,·) 이벤트가 판정에
  없어 owner_read 부류가 정적 green/동적 trap. 수정: interval liveness v2
  (§2의 S2). (커밋 237c2cf)
- **D3 (수정됨, 거짓음성) op 경계 — 차용 세탁.** 차용을 op에 넘겨 *참조를
  돌려받으면*(`var t be mut_ref u32 pass r .`) caller의 정적 판정이 별칭을
  잃어 t가 x를 차용한다는 사실을 놓쳤다 — `--check` green인데 VM은 ⚡
  (launder 픽스처). **수정의 근거가 곧 ESC-INV 접합**: E-ESCAPE가 "callee 지역을
  가리키는 참조는 반환 불가"를 보장하므로, 반환된 참조는 **반드시 인자에서
  유래**한다. 따라서 참조-타입 바인딩은 그 호출이 소비한 모든 차용의 **별칭**으로
  등록하면 건전하다(인자가 여럿이면 보수적으로 전부). 별칭 이름의 언급은 후보
  차용 전부의 use로 기록된다. 정상 세탁(살아 있는 동안 소유자 접근 없음)은
  green 유지 — 오탐 없음.
  · 남은 경계: callee가 차용을 *구조체 필드에 저장*하는 형태는 현 코어 문법에
    없다(참조 필드 미지원). 도입 시 L-ESC(이상화 스케치)의 field-store 규칙과
    함께 재논증 필요.
- **D4 (수정됨) 경로 비민감 오탐.** if 분기 한쪽의 own과 다른 분기의 use가
  가짜로 겹쳐 거부됐다(`branchy2`: 두 arm이 배타라 실행상 안전한데 E-EXCL).
  수정: 이벤트에 경로 문맥을 달고 배타 arm 짝을 충돌에서 제외(§2 compat),
  루프 간 공존은 S2L이 경로-무시로 유지. 건전성은 §8 전수 체크로 재확인.
- **D5 (수정됨, 거짓음성!) else-if 본문 미순회.** EXCL 순회가 BLOCK 자식만
  재귀해 `else if …`(FORM 자식)의 **본문 전체가 분석에서 누락**됐다 — 그 안의
  차용·소유자 접근이 보이지 않던 진짜 거짓음성. D4 작업 중 코드 검토로 발견,
  전용 arm 순회(excl2_if)로 수정 + 회귀 테스트.

## 7. 경험적 다리 — 퍼저는 이 정리의 표본 검증이다

`make test`의 400시드 퍼저는 §1 단편(+문자열/record/view/vec/차용-세탁 템플릿)의
프로그램을 생성해 "static-green ⇒ ⚡ 없음"을 실행으로 검사한다. 정리 A/B가
참이면 위반 0이어야 하며, 위반은 곧 (a) 본 증명의 반례 또는 (b) 구현이 §2/§3
모델에서 벗어난 버그다 — D1이 정확히 (b)로 발견된 사례. 현재 green 387/400, 위반 0.

## 8. V3-lite — 유계 전수 기계 검증 (2026-07-10 가동)

`impl/tests/run_tests.c`의 모델 체커가 §2 판정과 §3 ledger를 **독립 재구현**
(low_region/low_ir 코드 재사용 없음)하고, 유계 내 **모든** 이벤트 열에 대해
함의를 검사한다 — `make test` 상시 실행:

```
정리 A   : 지역 2·태그 ≤4·길이 ≤7 — 10,490,024 시퀀스 전수,
           static-green 625,800 전부 dyn-clean (위반 0; 보수 거부 119,326)
보조정리 B: prefix ≤2 + 루프본문 1..3 — 90,376 형태 × k=1..3 전개,
           S2L-green 70,416 전부 clean (위반 0; 본문 태그는 반복마다 신선)
경로 민감 : prefix ≤2 + arm A ≤2 + arm B ≤2 — 887,358 if-형태 전수,
           path-green 727,150 전부 *두 실행(arm A·arm B) 모두* clean (위반 0)
           ⇒ D4 수정(경로 민감 규칙)이 건전함을 유계 내 기계 확인
```

유계 밖(더 긴 열·태그 5+·중첩 루프)은 §4/§5의 종이 증명이 담당하고, 유계
안은 기계가 담당한다 — INV 케이스 오류·규칙 오기는 이 체커가 즉시 잡는다.

## 9. V3(완전 기계화) 준비물

- §2의 판정은 이벤트 열 위의 1차 술어(구간 산술)라 결정 가능 — Coq/Lean에서
  list 위 재귀 술어로 직역 가능한 형태로 유지했다.
- §3의 ledger는 stack-of-tags 소단계 의미 — Iris 없이도 순수 연산 의미로
  기계화 가능(동시성 없음). L-EXCL(이상화 스케치)과의 접합: place를 x에서
  proj-place로 일반화하면 본 문서의 정리 A가 스케치 §6.2 D2의 단편 사례.
- 우선 기계화 대상: INV 보존 5케이스(정리 A) — 가장 작고 결함 밀도가 높았던 곳.
